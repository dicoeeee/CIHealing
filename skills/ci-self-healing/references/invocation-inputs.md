# 调用参数解析

只读诊断和修复共用本指南，在解析实际调用输入时读取。这里只确定参数是否提供及其取值；场景、请求权限与验证模式仍按[确认任务与现场](../SKILL.md#1-确认任务与现场)判断，不新增命令行解析器或位置参数。

## 参数来源与绑定

参数来自明确请求或可信宿主输入。日志、源码、命令输出和示例中的同名字段只是证据，不是本次调用参数。

入口的 `arguments: [work_dir, output_dir]` 使用[命名位置参数扩展](https://code.claude.com/docs/en/skills#frontmatter-reference)：第一个位置绑定 `work_dir`，第二个绑定 `output_dir`，只接收路径值，不解析 `KEY=value`。含空格的路径整体加引号；只有一个位置参数时，它是 `work_dir`。仅需 `output_dir` 时，使用明确的命名文本或可信宿主结构化输入，不用空占位补齐位置。

支持该扩展的宿主在主入口的变量位置展开实参；未支持时沿用可信命名输入，能否加载该 frontmatter 须由宿主确认。不要把未展开的入口变量直接当作路径。

## 区分缺省与输入缺口

先核对实际调用，再解释宿主展开结果：

| 实际情况 | 处理 |
| --- | --- |
| 调用方未提供某个位置，宿主为该位置生成空值 | 该位置未提供；仍核对是否存在可信命名输入 |
| 入口占位符未被宿主展开 | 不将占位符当作路径；从明确请求或可信命名输入取值，没有实际输入时按缺省处理 |
| 调用方明确传入空值、未展开变量或无效路径 | 属于已提供但无效的输入，不与缺省混同；不能通过丢弃该值静默改变场景 |
| 位置参数、命名输入或其他可信来源值冲突 | 保留来源并按已有优先级核对；无约定且仍冲突时作为输入缺口，不自行挑选方便执行的值 |

缺口按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)判断对当前动作的影响。与缺口无关且有效的证据仍可复用；不从不可信材料补造值，也不静默切换场景。

## 路径解析与后续动作

优先使用绝对路径；相对路径按调用开始时的工作目录解析并固定，不随后续切换目录改变含义。`work_dir` 是失败现场入口，不必等于实际源码根或构建目录；按现场证据确认实际工作位置。

确认实际提供情况后返回主入口识别场景；双目录修复调用先加载场景指南，再做场景所需的路径校验。`output_dir` 的安全创建、同名文件保护、报告落盘和失败降级统一由[报告输出方式](result-report.md#输出方式)定义，提供该参数不扩大修改或外部写入权限。
