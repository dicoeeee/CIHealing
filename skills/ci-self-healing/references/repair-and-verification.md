# 修复准入与验证

仅用于已授权修复。评估准入前完整读取[通用诊断流程](diagnosis-and-repair.md)并完成适用主动取证，未读全先补读。写入式实验、候选修改或发布前，读取固定的[企业修复策略入口](enterprise-policy.md)，将适用性/动作限制纳入准入，后续复核也按该指南；入口缺失或不可读则暂停相关写入，按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)处理。

## 修复依据

评估实验或候选准入前读取[修复依据核查](repair-basis.md)，进入候选前完成其判断。诊断和准入记录合起来须可核查：

1. **目标行为**及来源，区分直接声明、观察、推断。
2. **修复位置**、限制来源及重要替代方向/反证的取舍依据。
3. **修改约束**：保留行为、兼容性、授权与企业策略依据；受影响文件/配置/依赖/下游、风险及恢复方式。
4. **验证计划**：能检验目标和根因修复、证伪候选的检查/通过条件，可在所选模式执行。准备形成候选或开展构建/验证时，先完整读取[候选实施与分层验证](candidate-verification.md)，再确定层级、位置和通过条件；明确只读停止时跳过。
5. **关键缺口**：未知项对选择、保留行为和必要验证的影响；未解决的[语义方向歧义](repair-basis.md#语义方向歧义)等关键缺口阻断候选，按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)处理。

按缺口调查；`diagnosis` 保存机制、目标、约束与证据，`repair_admission` 引用它并记录决定/验证计划，候选与报告复用。新候选、目标变化或重要新证据出现时，在相应修改/发布前重评，仅更新受影响内容。旧收据保留，适用性按[收据绑定与失效](core-contracts.md#收据绑定与失效)核对；准入允许试修，不表示验证正确。

## 候选修改前的准入记录

首次候选修改前，在宿主可观察的消息、日志、记录或事件中输出 `repair_admission`，绑定失败/基线，引用诊断、目标、约束和验证计划。准入的策略依据引用已完整读取的[固定策略入口](enterprise-policy.md)及实际声明；未读或入口缺失不能记作未配置，明确未配置也不豁免通用限制。按“目标行为及证据支持关系 → [完整候选与缺口](repair-basis.md#完整候选与缺口) → 决定”组织；不能只留内部判断或报告事后补写。无宿主指定格式时可简写，不新增文件或重复 YAML。

[语义方向歧义](repair-basis.md#语义方向歧义)统一规定消解证据；有据的局部修正无需强列两种解释。写入式实验事前记录 `experiment_only` 及确认的范围，不授予候选/发布准入；格式完整或 `allow` 字段本身不证明可放行。

## 决定修复准入

决定只绑定具体动作/范围。候选修改或发布为 `stop` 时，权限/预算内的独立取证仍可继续；写入式实验须另行满足下方 `experiment_only` 条件并事前记录，不解除候选停止。新证据解决缺口后才重评候选。已转入[案例建议分支](../SKILL.md#案例建议分支)时，本轮不再按下方继续/重评规则放行实验、候选或发布，仅保留停止决定、只读补证和既有恢复清理义务。

```yaml
repair_admission:
  evidence_refs: [] # 关键判断及材料具体内容的支持关系；可引用已有诊断
  unknowns: [] # 对完整候选行为的影响；非阻塞须说明在仍有依据的不同解释下为何均成立
  required_verification: []
  rationale: <目标行为、重要替代解释的取舍与证据；不能用结论替代依据>
  decision: experiment_only | allow_local_candidate | allow_remote_candidate | stop
```

- `experiment_only`：权限、策略、范围及可逆性可独立确认的实验/临时插桩，说明区分的问题及为何不依赖未决目标。写前满足[恢复](execution-modes.md#基线与候选恢复)和[清理前置条件](workspace-cleanup.md#执行前条件)，结束处理改动/副产物并回诊断；未经另行候选准入不作为候选/发布，不绕过禁修、授权或实施未获准语义修复。
- `allow_local_candidate`：失败/基线准确绑定，上述依据充分、无语义方向歧义；定位足以行动且根因 `confirmed`/`supported`，或确定性工具直接指出机械修正。两者都不替代目标证据。允许创建未验证候选，原失败可在所选模式允许处复验。
- `allow_remote_candidate`：满足本地准入，实际候选通过 V0、明确的发布前本地检查及差异/策略检查；确定远端必需检查和准确候选绑定，满足[远端授权](remote-verification.md#授权与能力)。必需预检失败/未完成不发布。
- `stop`：暂停依赖未决语义、依据或权限的修改/发布，注明范围；独立取证按上述规则继续，新证据/授权解决缺口后重评，否则按入口[停止分支](../SKILL.md#停止分支)处理。无候选、无写入式实验/构建副作用时，`required_verification` 可为空并说明未执行原因，不为填计划加载验证/清理指南；已有写入仍履行恢复与清理义务。

关键缺口仍影响决定时 `allow` 无效。解除停止或改非阻塞须按[完整候选与缺口](repair-basis.md#完整候选与缺口)和[语义方向歧义](repair-basis.md#语义方向歧义)核对新增或重新核对的区分性证据，记录解决的问题及决定变化；机制明确但目标不明时保留机制判断，停止依赖目标的候选。

已完整读取且仍适用的候选指南可复用；取证工具、实验或候选验证实际失败后，在选择后续动作前读取[失败后的处理](verification-failures.md)。

## 结果判定

报告 `local_verified` 或 `outer_ci_passed` 前，按完整实际修改复核修复依据/准入、原记非阻塞的未知项、影响目标/方向/必要验证的新证据及重要反证，简记结论和引用；仅更新受影响部分，不重做全量调查。

两种成功结果均要求无[语义方向歧义](repair-basis.md#语义方向歧义)或其他关键缺口，并满足[清理条件](workspace-cleanup.md#结束与协作)。准入、验证和清理各自成立：编译/外层 CI 不豁免清理，解释差异不替代最新有效 `match`。预期独立于候选且能区分方向的适用测试可提供目标证据；通过本身不证明这种区分力。

| 结果 | 成立条件 |
| --- | --- |
| `not_eligible` | 已确认属于重试、Flaky、基础设施、事故或其他非修复路径 |
| `local_verified` | `local_verify` 中 V0、V1 及所有适用且已声明的 V2/V3 在当前工作空间环境实际通过 |
| `outer_ci_passed` | `remote_verify` 中发布前检查通过，V1、必需 V2/V3 在计划指定位置实际通过，且准确候选对应的 V4 通过；不要求先取得 `local_verified` |
| `no_progress` | 后续候选尝试不再增加有用证据或策略 |
| `inconclusive` | 证据、环境、领域知识、能力或必要验证不足，无法给出完整修复结论 |
| `denied` | 必要动作被适用策略禁止，或策略允许申请的必要授权被拒绝 |

案例建议不构成修复成功；修复调用保留实际受阻原因并按上表判定，建议尚未实施、必要验证不足时为 `inconclusive`，已有禁令或无进展按各自条件判定，不新增建议专用结果码。

语义歧义未解决时，依赖该选择的候选修改与发布保持 `stop`；独立诊断实验的准入不改变这一结论，即使 V1/V2 或 V4 通过也不成立上述成功结果。保留已通过检查的观察事实，按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)补证、请求澄清、移交或结束；因该缺口无法继续而结束调用时返回 `inconclusive`，不把行动决定、协作请求和终局结果混为一谈。

必需检查未触发、跳过、取消或缺少有效证据时，不成立成功结果，即使流水线汇总为 `passed`。实际失败保留失败事实；运行仍排队或执行时按预算观察，无法取得必要证据时按关键缺口规则处理。

协作中的请求与部分结果不强行包装成整次修复终局结果，遵循 [交互与移交](collaboration.md#交互与移交)。`queued` / `running` 是带观察时间的进度，后续观察责任见 [Provider 合同](provider-contract.md#实时观察边界)。
