# 修复准入与验证

仅用于已授权修复。评估准入前完整读取[通用诊断流程](diagnosis-and-repair.md)并完成适用主动取证，未读全先补读。写入式实验、候选修改或发布前，读取固定的[企业修复策略入口](enterprise-policy.md)，将适用性/动作限制纳入准入，后续复核也按该指南；入口缺失或不可读则暂停相关写入，按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)处理。

## 修复依据

评估实验或候选准入前读取[修复依据核查](repair-basis.md)，进入候选前完成其判断。诊断和准入记录合起来须可核查：

1. **目标行为**及来源，区分直接声明、观察、推断。
2. **修复位置**、限制来源及重要替代方向/反证的取舍依据。
3. **修改约束**：保留行为、兼容性、授权与企业策略依据；受影响文件/配置/依赖/下游、风险及恢复方式。
4. **验证计划**：能检验目标和根因修复、证伪候选的检查/通过条件，可在所选模式执行。
5. **关键缺口**：未知项对选择、保留行为和必要验证的影响；未解决的[语义方向歧义](repair-basis.md#语义方向歧义)等关键缺口阻断候选，按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)处理。

按缺口调查；`diagnosis` 保存机制、目标、约束与证据，`repair_admission` 引用它并记录决定/验证计划，候选与报告复用。新候选、目标变化或重要新证据出现时，在相应修改/发布前重评，仅更新受影响内容。旧收据保留，适用性按[收据绑定与失效](core-contracts.md#收据绑定与失效)核对；准入允许试修，不表示验证正确。

## 候选修改前的准入记录

首次候选修改前，在宿主可观察的消息、日志、记录或事件中输出 `repair_admission`，绑定失败/基线，引用诊断、目标、约束和验证计划。按“目标行为及证据支持关系 → [完整候选与缺口](repair-basis.md#完整候选与缺口) → 决定”组织；不能只留内部判断或报告事后补写。无宿主指定格式时可简写，不新增文件或重复 YAML。

[语义方向歧义](repair-basis.md#语义方向歧义)统一规定消解证据；有据的局部修正无需强列两种解释。写入式实验事前记录 `experiment_only` 及确认的范围，不授予候选/发布准入；格式完整或 `allow` 字段本身不证明可放行。

## 决定修复准入

决定只绑定具体动作/范围。候选修改或发布为 `stop` 时，权限/预算内的独立取证仍可继续；写入式实验须另行满足下方 `experiment_only` 条件并事前记录，不解除候选停止。新证据解决缺口后才重评候选。

```yaml
repair_admission:
  evidence_refs: [] # 关键判断及材料具体内容的支持关系；可引用已有诊断
  unknowns: [] # 对完整候选行为的影响；非阻塞须说明在仍有依据的不同解释下为何均成立
  required_verification: []
  rationale: <目标行为、重要替代解释的取舍与证据；不能用结论替代依据>
  decision: experiment_only | allow_local_candidate | allow_remote_candidate | stop
```

- `experiment_only`：权限、策略、范围及可逆性可独立确认的实验/临时插桩，说明区分的问题及为何不依赖未决目标。写前满足[恢复](execution-modes.md#基线与候选恢复)和[清理前置条件](workspace-cleanup.md#执行前条件)，结束处理改动/副产物并回诊断；未经另行候选准入不作为候选/发布，不绕过禁修、授权或实施未获准语义修复。
- `allow_local_candidate`：失败/基线准确绑定，上述依据充分、无语义方向歧义；定位足以行动且根因 `confirmed`/`supported`，或确定性工具直接指出机械修正。两者都不替代目标证据。允许创建未验证候选，原失败可在所选模式允许处复验。
- `allow_remote_candidate`：满足本地准入，实际候选通过 V0、明确的发布前本地检查及差异/策略检查；确定远端必需检查和准确候选绑定，满足[远端授权](remote-verification.md#授权与能力)。必需预检失败/未完成不发布。
- `stop`：暂停依赖未决语义、依据或权限的修改/发布，注明范围；独立取证按上述规则继续，新证据/授权解决缺口后重评，否则按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)协作或结束。

关键缺口仍影响决定时 `allow` 无效。解除停止或改非阻塞须按[完整候选与缺口](repair-basis.md#完整候选与缺口)和[语义方向歧义](repair-basis.md#语义方向歧义)核对新增或重新核对的区分性证据，记录解决的问题及决定变化；机制明确但目标不明时保留机制判断，停止依赖目标的候选。

## 构建与更新候选

依据已记录的决定实施候选，保留与其对应的修复依据及验证计划。候选指相对于介入时工作空间的完整修改集合，恢复和修改归属统一遵循 [执行模式](execution-modes.md#基线与候选恢复)，不额外要求生成 Patch 文件。

在符合目标与约束的方案中选影响较小的修改，综合比较依赖影响、行为变化、额外机制、运行时处理与维护负担，不以文件数或增删行数单独判断。测试、断言、策略或检查只有在当前意图和证据表明它们本身错误时才应调整，不以压制失败作为修复目的。

## 分层验证

| 层级 | 目的 |
| --- | --- |
| V0 Candidate Guard | 检查基线、实际差异、路径、策略、语法、Schema 和候选身份 |
| V1 Root Failure | 通过当前有效入口复验原失败目标及其验收要求 |
| V2 Affected Scope | 运行受影响测试、调用方、依赖检查、配置验证或 dry-run |
| V3 Broader Scope | 在已声明或确有必要时，运行更广的回归或下游检查 |
| V4 Outer CI | 观察准确发布候选对应的宿主流水线或 Required Checks |

V1 以原失败目标、配置及验收范围为基准，通常重跑原命令/任务/PoC/检查。获准修正构建规则、参数或入口后，按当前项目配置生成有效动作，记录变化依据及与原目标的对应；不机械重放失效命令，也不临时手改命令绕过配置、跳过阶段、缩小验收或降低条件。局部检查不替代 V1，无法完成则记录缺口。

`required_verification` 逐项列检查标识、层级、命令或 Job/Check、位置（`local`/`remote`）、是否必须发布前完成及通过条件。V0 与仓库/Harness 声明的发布前本地检查必须先于发布；位置选择不减少要求。

参数去留、值传递、接口行为或配置含义的修复，V2 须含能检验该决定的针对性检查；共享接口覆盖调用方兼容性。预期来自已确认目标/契约，不能由候选反推；独立遗留问题按实际关联判断是否影响必要验证。

V1/V2/适用 V3 可由 V4 具体任务承担，无需本地重复，但逐项映射准确候选。收据按核心合同绑定位置、命令/任务、结果和未执行/未完成原因：本地未执行记 `not_run` 并说明远端承担项，启动未完成记 `incomplete`；远端通过不改写本地事实或抹去失败，本地通过只证明预检范围。

会写源码工作空间的诊断、构建或验证，执行前读取[清理与校验](workspace-cleanup.md)，将工作空间校验列为必需检查，与构建结果分别记录；成功与缺口出口见其[结束与协作](workspace-cleanup.md#结束与协作)。

## 失败后的路径选择

区分原 CI、候选验证与工具执行失败，保留步骤、结果、候选身份及证据。结合差异、依赖、基线与实际结果判断新失败为 related/unrelated/uncertain 并说明依据，再按表选择；多阻塞分别处理，不要求遍历所有路径。

| 当前证据 | 下一步与停止条件 |
| --- | --- |
| 取证工具不可用、超时或响应不全 | 复用有效材料，按[Provider 访问](providers/provider-access.md#选择访问方式)补缺口，不重做全部取证；无获准替代且影响判断则协作/结束，不换工具绕过拒绝 |
| 验证反驳候选或关键前提 | 更新诊断、撤销受影响准入；放弃候选先按[恢复规则](execution-modes.md#基线与候选恢复)恢复/核对，再在有据新策略及预算内重新准入下一候选；无进展则结束 |
| 环境、工具或无关失败阻断验证，候选未被判定 | 保留有据候选/真实结果，在既有模式/授权内寻找满足同一要求的路径；无法完成则报告缺口，不删检查、降条件或因本地缺环境转远端发布 |
| 新证据造成目标/方向关键歧义 | 暂停相关修改/发布，按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)补区分性证据；未解则澄清/移交/结束，不换候选试绿代替意图判断 |
| 策略禁止、必要授权被拒或适用性未决 | 按[企业策略](enterprise-policy.md#判断与行动)和[交互与移交](execution-modes.md#交互与移交)处理，不借换工具、Agent 或重试绕过 |

发布/触发结果不明先[远端核对](remote-verification.md#外部动作结果不明时)，不按普通失败重试；恢复不安全则暂停相关写入，不叠加被放弃候选残留。

Fallback 仅限既有授权、有据替代或有界重试，记录缺口和新结果，不机械重复无新信息动作。共用[调用限额](core-contracts.md#调用身份与限额)，不重置身份/预算；协作复用[复核请求](execution-modes.md#复核请求与继续条件)，结束按下方结果判定。一次工具失败不证明原问题是非修复路径。

## 结果判定

报告 `local_verified` 或 `outer_ci_passed` 前，按完整实际修改复核修复依据/准入、原记非阻塞的未知项、影响目标/方向/必要验证的新证据及重要反证，简记结论和引用；仅更新受影响部分，不重做全量调查。

两种成功结果均要求无[语义方向歧义](repair-basis.md#语义方向歧义)或其他关键缺口，并满足[清理条件](workspace-cleanup.md#结束与协作)。准入、验证和清理各自成立：编译/外层 CI 不豁免清理，解释差异不替代最新有效 `match`。预期独立于候选且能区分方向的适用测试可提供目标证据；通过本身不证明这种区分力。

| 结果 | 成立条件 |
| --- | --- |
| `not_eligible` | 已确认属于重试、Flaky、基础设施、事故或其他非修复路径 |
| `local_verified` | `local_verify` 中 V0、V1 及所有适用且已声明的 V2/V3 在当前工作空间环境实际通过 |
| `outer_ci_passed` | `remote_verify` 中发布前检查通过，V1、必需 V2/V3 在计划指定位置实际通过，且准确候选对应的 V4 通过；不要求先取得 `local_verified` |
| `no_progress` | 后续候选尝试不再增加有用证据或策略 |
| `inconclusive` | 证据、环境、领域知识、能力或必要验证不足，无法给出完整修复结论 |
| `denied` | 必要动作被适用策略禁止，或策略允许申请的必要授权被拒绝 |

语义歧义未解决时，依赖该选择的候选修改与发布保持 `stop`；独立诊断实验的准入不改变这一结论，即使 V1/V2 或 V4 通过也不成立上述成功结果。保留已通过检查的观察事实，按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)补证、请求澄清、移交或结束；因该缺口无法继续而结束调用时返回 `inconclusive`，不把行动决定、协作请求和终局结果混为一谈。

必需检查未触发、跳过、取消或缺少有效证据时，不成立成功结果，即使流水线汇总为 `passed`。实际失败保留失败事实；运行仍排队或执行时按预算观察，无法取得必要证据时按关键缺口规则处理。

协作中的请求与部分结果不强行包装成整次修复终局结果，遵循 [交互与移交](execution-modes.md#交互与移交)。`queued` / `running` 是带观察时间的进度，后续观察责任见 [Provider 合同](provider-contract.md#实时观察边界)。
