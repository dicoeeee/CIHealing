# 文字版结果报告

本文件定义最终报告的填写规则、输出位置与交付检查；固定排版以[报告模板](../assets/analysis-fix.template.md)为唯一来源。报告汇总影响结论的重要事实和尝试，按需引用过程记录；无需复述全部 Attempt 或工具调用。

## 交付时机

本次调用结束时交付报告，包括只读诊断，以及修复成功、未解决、非修复路径、权限不足或限额耗尽。等待用户答复时仅报告当前事实与请求，保留本次调用；子 Agent 移交并结束子任务时交付本次报告，标明整次修复的未完成事项。协作行为与实际提交情况按[交互与移交](execution-modes.md#交互与移交)记录。

输出目录、同名文件保护、校验范围冲突与文件交付失败的处理统一见[报告输出准备](output-delivery.md)。使用文件输出前读取，已核对且仍有效的布局可复用；未提供 `output_dir` 时直接在宿主消息中交付同结构完整报告。

## 固定结构

生成完整报告前读取[报告模板](../assets/analysis-fix.template.md)，替换所有 `{{REPORT:…}}` 占位符。确定性约束只覆盖一级标题、六个二级章节的名称和顺序、记录区必需字段，以及适用表格的列名和分类初始/最终两行。本文件下方的三级标题仅组织填写说明，不作为报告标题层级。

章内正文由 Agent 按实际问题自主组织，可用段落、列表、三级及更深小节、补充对比表、代码和证据引用；不固定字段标签、讲述顺序、段落数量或篇幅。模板占位内容和下方各节说明用于提示应覆盖的事实，不要求逐条改写成表单。六章均须有实质内容；无修改、未验证或不适用时简要说明即可。表达自由不减少证据、准入、验证和缺口披露要求。

记录信息和仓库与候选表始终保留；记录信息保留模板中的必需字段及相对顺序，可按已知事实增加生成时间、运行场景、执行者角色等有助理解本次报告的行。请求类型填“仅诊断”或“修复”。多仓或多个候选在仓库表逐行绑定，其余章节沿用这些标识；无法识别仓库时用未知项及原因保留该事实。`work_dir` 不等于实际源码路径，未提供的目录参数注明“不适用：未提供”。仅诊断不要求建立修复身份与候选。

空项使用明确表述：**不适用**表示当前任务无需该信息；**未知**表示应确认但未取得依据；**未执行**表示动作或检查没有执行。均说明原因；已开始但未取得完整结果写“未完成”并说明缺口。不用空白、单独的破折号或占位符代替事实，也不为填表编造身份、分类、准入或结果。

模板中的条件表格与分组按以下规则使用：

- **远端运行表**：`remote_verify` 保留并逐行绑定仓库/候选；未发布或未触发也保留实际缺口。其他模式删除该表及其标题，原始 CI 运行证据仍写第 2 节。
- **失败对象块**：第 2 节单个对象可直接行文；多个对象时按模板的“失败对象”三级标题分别组织，避免混用身份和分类依据。是否保留分类表由该对象本次是否有分类交付要求决定：存在固定绑定或可信调用的分类要求时，保留初始/最终两行及 Profile、变化和交付完成度说明。配置缺口、入口不可读、标准范围不适用、未匹配或小类未确定均不能取消该要求；按实际情况记录未应用标准、待定或未完成及原因。只有既无固定绑定也无本次分类要求时，才删除分类专用内容并简要说明依据。
- **修改说明**：有实际修改、继承候选或需要说明的原有修改时，逐文件说明归属、作用和交付状态，可使用模板修改表，也可用列表或正文表达；不用该表时删除。完全没有需记录的修改时说明原因。清理与恢复事实可合并组织。
- **检查表**：有已声明或实际执行的检查时保留，必要检查未执行也列行说明。可按仓库、候选或检查范围拆成多张表，各表使用模板的相同列名和顺序，并通过小节或表内信息明确绑定；不因拆表遗漏必要检查。既无检查计划也未执行检查时删除表并说明原因。适用的工作空间校验及缺口可在表内或正文中组织。

多行日志和代码放在表格外，通过位置引用关联；表格单元格中的 `|` 写为 `\|`，包括行内代码中的竖线。模板只固定呈现形式，不改变分类、准入、验证或结果判据。

### 1. 处理结论

当前结论、一句话说明和本次调用是否结束。修复调用沿用[结果判定](repair-and-verification.md#结果判定)；仅诊断写明“仅诊断，未执行修复”，不套用修复终局结果。

### 2. 失败与根因

原始失败任务或命令、关键报错、根因判断及证据；区分观察事实、受支持的判断和未确认部分。

- **CI 证据**：引用实际 Provider（或未知）、run/Job/重试身份、本地/MCP/CLI 来源与日志完整性。复用已有快照和访问记录；读取失败不等于原始 CI 失败的根因。
- **日志片段**：按[引用与读取局限](failure-evidence-extraction.md#引用与读取局限)标注原始位置及影响结论的缺口，引用已核对的原文与观察，不复制提取 JSON 全文。
- **分类情况**：对本次要求分类的对象，复用[初始分类与最终分类](failure-classification.md#初始分类与最终分类)记录，交代实际 Profile 标识、版本、入口及绑定来源，并使用模板分类表。初始分类保留首次路径、当时判据和证据，允许没有小类；最终分类填写复核的小类及父级路径、当前判据和证据，无法确定时保留真实判断并标注未完成。初始记录缺失如实说明，不用最终结果倒填。

无变化也保留初始和最终两行，在表内或表后说明分类变化及原因，以及最终分类交付已完成还是未完成。分类完成度和修复结果按[分类与修复边界](failure-classification.md#分类与修复边界)分别判定；分类修正所影响的准入和验证分别在第 3、5 节体现。

### 3. 目标行为与修复依据

目标行为及来源、所选方向与约束、重要相反方向的取舍或仍需的区分性证据。修复调用引用实际已有的准入记录，报告最终复核结论及重要反证的处置；尚未形成准入时如实注明。最终报告不能替代修改前必须输出的[准入记录](repair-and-verification.md#候选修改前的准入记录)。

修复调用复用[策略记录](enterprise-policy.md#判断与行动)，未配置时简记；其实际判断应与结论、修改/恢复及交接一致，不在报告阶段另行放行。仅诊断可引用已核对的策略事实，不因此进入修复准入。

### 4. 实际修改

列明文件、修改及作用，区分用户/Job 原有内容、继承候选和本次修改；说明交付时保留、已恢复和未恢复的内容。未修改时说明原因。

需要[工作空间清理与校验](workspace-cleanup.md)时，在此记录实际删除/恢复及保留依据。CI Job 还须明确实际留在指定工作空间的代码；后续 Patch 提取责任写入第 6 节。

### 5. 验证结果

按模板检查表逐项列检查、实际结果、覆盖范围和证据；必要检查未执行或未完成时说明原因。区分本次检查、原始失败与复用的历史证据。没有检查时按上述裁剪规则说明原因，不创建虚构的验证行。

修复验证证据按[收据绑定与失效](core-contracts.md#收据绑定与失效)关联候选、环境和观察时间；证据定位到文件位置、提交、MR 材料或检查记录。流水线状态引用实际观察，不由本地检查推导。

需要工作空间校验时，列实际取得的检查根、基准清单与原摘要、调用/候选绑定、最新脚本结论及时间，与编译结果分开。应执行但未采集或未完成校验也须说明。不复制完整清单，不把 `match` 扩大为无历史冗余、Patch 已提取或修复正确。若最新有效结果仍是 `mismatch` / `incomplete` 或缺失，即使差异已被解释、编译已通过，也不能把清理或整体修复写成通过；按[清理出口](workspace-cleanup.md#结束与协作)保留实际检查成功与最终未完成的区别。

发生过基准缺失或时序错误时，保留该过程事实；若已按[恢复路径](workspace-recovery.md#基准缺失或时序错误的恢复)纠正，说明重建依据、新基准、重验和最终校验。恢复后可按实际满足的条件判断交付，不把历史过程改写成首次即合规。

### 6. 剩余问题与交接

说明缺口、影响及继续所需的信息、权限或检查；协作时列接收方、具体请求、实际提交情况和未完成事项。“无剩余项”仅指本次任务与验证范围。按本次实际情况补充：

- CI 访问能力缺口、已尝试路径及继续所需条件。
- 未确定小类、未匹配、标准未应用或初始记录缺失等分类交付缺口及影响。
- 清理残留、读取缺口、范围外或历史产物问题，以及未恢复项。
- 原生 clean 的执行或跳过原因、本次独立目录和临时产物的回收收据、必要保留项及证据完整性。源码一致、进程退出和文件回收分别说明，不以任一通过代替另两项。
- CI Job 的后续 Patch 提取责任和未覆盖的外层检查；远端验证是否仍需观察及实际续接条件。

## 交付检查

1. 按模板填入已经复核的事实，按本次适用条件裁剪，核对结论、修改和检查对应同一组仓库与候选。
2. 按下方[格式校验](#格式校验)检查最终正文，修正偏差后重新检查。任何修改都会使此前的格式检查不再覆盖最新正文。
3. 复核关键结论的证据、重要缺口与未恢复项。要求分类时，按[分类标准边界](failure-classification.md#分类标准边界)核对实际 Profile、标准路径及判据与证据的对应关系，最终小类有据或明确标记未完成。修复结果符合既有判据，分类交付、协作提交与整次修复完成分开表达。
4. 文件交付读回最终内容，确认属于本次调用且与格式检查覆盖的正文一致，再提供真实路径；纯文字或降级交付输出同结构完整正文。另有声明产物时确认实际存在；文件交付失败如实披露，保留修复与验证的观察事实。

文件已写完且不再修改时，格式校验与最终读回都是只读动作，可在同一轮执行，随后依据实际结果完成事实复核；两者必须覆盖同一份最终正文，修改后均需更新。文件交付的最后消息只需结论摘要、关键缺口和实际绝对路径，不复述报告或再次展开已完成的诊断。发现实质问题仍须纠正或披露，不能为及时结束跳过校验或声称成功。

### 格式校验

使用包内 [report_check.py](../scripts/report_check.py) 只读检查报告。需要 Python 3.9+，无第三方依赖；脚本读取包内模板作为结构依据，不写入或修改报告，不执行报告中的命令，不访问引用的证据。通过宿主指定的脚本工具执行 `scripts/report_check.py`，参数以 `--help` 为准。以下是有序参数，路径替换为实际位置：

```json
["--report", "/approved/output_dir/analysis-fix.md",
 "--classification", "required", "--checks", "present"]
```

`--classification` 和 `--checks` 来自当前任务、分类要求和验证计划，不能根据报告漏写了什么反推：

- 所有对象本次都有分类交付要求时传 `required`，全部没有要求才传 `none`；多对象中只有部分有要求时传 `mixed`。按上述失败对象块规则判断，标准是否可用或适用于当前对象不决定此参数；已有要求但标准无法应用时仍保留表格。Agent 核对各对象的要求和绑定，脚本仅检查各分组中的表格存在性与格式。
- 有已声明或实际执行的检查传 `present`，包括必需检查未执行的情况；既无检查计划也未执行检查才传 `none`。

脚本检查固定标题与章节、记录区必需字段、适用表格及列数、分类初始/最终两行、模板占位符与文件名；不校验章内字段标签、叙述顺序或表达风格。返回 JSON 和退出码：`valid` / 0 表示这些结构检查通过；`invalid` / 1 列出可定位的格式问题；`incomplete` / 2 表示输入、模板或读取条件不足。输出绑定所读正文的 SHA-256。它不校验 Profile 类别是否合法、证据真实性、修复正确性或语义完整性，结构通过不能替代上方事实复核。

纯文字或文件交付失败时，可将完整正文通过标准输入传给 `--report -`，无需新增文件；传输须保留正文原样并避免 shell 展开其中的命令。宿主不支持安全传入正文、Python/脚本不可用或读取失败时，对照模板检查后照常交付，并在第 6 节说明格式校验未完成及原因。格式错误由 Agent 修正；无法在本次限额内修正时如实交付现有事实并披露格式缺口，不声称规范交付已完成。

格式检查收据留在宿主输出即可，不新增必交文件。若需说明校验缺口，在第 6 节记录；格式检查不作为 CI 构建验证，也不改变修复结果。Skill 文本要求执行检查，但不能保证工具调用不被跳过；需要强制交付门槛时由宿主落实。
