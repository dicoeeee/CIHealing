# 文字版结果报告

本文件统一定义最终报告的结构、输出位置与交付检查。报告汇总影响结论的重要事实和尝试，按需引用过程记录；无需复述全部 Attempt 或工具调用。

## 交付时机

本次调用结束时交付报告，包括只读诊断，以及修复成功、未解决、非修复路径、权限不足或限额耗尽。等待用户答复时仅报告当前事实与请求，保留本次调用；子 Agent 移交并结束子任务时交付本次报告，标明整次修复的未完成事项。协作行为与实际提交情况按[交互与移交](execution-modes.md#交互与移交)记录。

## 输出方式

| 调用输入或实际情况 | 交付动作 |
| --- | --- |
| 提供有效且可安全写入的 `output_dir` | 在解析并校验后的 `output_dir` 目录内写入 `analysis-fix.md`；宿主消息给出结论摘要与实际绝对路径。 |
| 未提供 `output_dir` | 在宿主消息中直接输出同结构的完整 Markdown 报告，不自行选择落盘目录。 |
| 已提供的路径无效、无法安全写入或写入失败 | 在宿主消息中输出完整报告并说明目标路径、原因和文件交付缺口；不声称文件已生成，不静默改名或换目录。 |

先按[入口参数规则](../SKILL.md#调用参数与报告输出)区分未提供与无效输入，再解析输出目录：相对路径按调用开始时的工作目录固定，优先采用绝对路径。只有有效目录才能与报告文件名组合；缺省或无效时按上表文字交付，不从空值拼接路径。其他构建产物和日志的位置由对应场景决定。

只在授权范围内创建或写入目录，保留已有内容；同名文件须确认属于本次调用且可安全更新，否则按交付缺口处理。推荐每次调用使用独立输出目录，置于源码工作空间之外。若位于源码内，确认报告不参与或改变构建输入，将其与候选修改区分，并在需要 Patch 提取时说明排除范围；目录名本身不是排除依据。

报告保留必要且可定位的证据引用，敏感信息遵循[入口硬边界](../SKILL.md#保持硬边界)。明确提供输出目录仅授权报告交付，不改变只读诊断、修复或外部写入的权限边界。

## 固定结构

标题为“CI 自愈诊断与修复报告”。先列记录信息，再按顺序保留以下六个二级章节；无修改、无候选或未验证时，在对应章节写明事实与原因。

记录信息：`invocation_id`、请求类型、执行模式、仓库及实际工作空间绝对路径、`baseline_sha`、候选 fingerprint。多仓或多个候选分别绑定；仅诊断不要求建立修复身份与候选。不适用字段标为“不适用”，应有但无法确认的信息标为“未知”并说明原因。

| 二级章节 | 必须回答的内容 |
| --- | --- |
| 1. 处理结论 | 当前结论、一句话说明和本次调用是否结束。修复调用沿用[结果判定](repair-and-verification.md#结果判定)；仅诊断写明“仅诊断，未执行修复”，不套用修复终局结果。 |
| 2. 失败与根因 | 原始失败任务或命令、关键报错、根因判断及证据；区分观察事实、受支持的判断和未确认部分。 |
| 3. 目标行为与修复依据 | 目标行为及来源、所选方向与约束、重要相反方向的取舍或仍需的区分性证据。修复调用引用实际已有的准入记录，报告最终复核结论及重要反证的处置；尚未形成准入时如实注明。 |
| 4. 实际修改 | 文件、修改及作用，区分用户/Job 原有内容、继承候选和本次修改；说明交付时保留、已恢复和未恢复的内容。未修改时说明原因。 |
| 5. 验证结果 | 逐项检查、实际结果、覆盖范围和证据；必要检查未执行或未完成时说明原因。区分本次检查、原始失败与复用的历史证据。 |
| 6. 剩余问题与交接 | 缺口、影响及继续所需的信息、权限或检查；协作时列接收方、具体请求、实际提交情况和未完成事项。“无剩余项”仅指本次任务与验证范围。 |

涉及 CI 证据获取时，第 2 节引用实际 Provider（或未知）、run/Job/重试身份、本地/MCP/CLI 来源与日志完整性；第 6 节补充影响结论的访问能力缺口、已尝试路径及继续所需条件。复用已有快照和访问记录，不要求重复表单；读取失败不等于原始 CI 失败的根因。

使用日志片段时，按[引用与读取局限](failure-evidence-extraction.md#引用与读取局限)标注原始位置及影响结论的缺口；报告引用已核对的原文与观察，不复制提取 JSON 全文。

存在固定绑定或本次分类要求时，在第 2 节增加“分类情况”，复用[初始分类与最终分类](failure-classification.md#初始分类与最终分类)记录。每个失败调查对象列明实际 Profile 标识、版本、入口、绑定来源及失败引用，并分别展示：

| 判断 | 分类路径（标准中的各级编号和名称） | 依据与未确定项 |
| --- | --- | --- |
| 初始分类 | 首次记录的路径；允许没有小类，缺少时标注“小类未确定” | 当时的证据、满足的判据与候选/缺口；初始记录缺失则如实说明 |
| 最终分类 | 交付前复核的小类及父级路径；无法确定时保留实际判断并标注未完成 | 最终证据与判据、候选或共存关系，以及仍有的缺口 |

表后注明“分类变化及原因”和“最终分类交付：已完成/未完成”；无变化也保留两行。第 6 节披露未确定小类、未匹配、标准未应用或初始记录缺失等交付缺口及影响；第 3、5 节反映分类修正所影响的准入与验证。分类完成度和修复结果按[分类与修复边界](failure-classification.md#分类与修复边界)分别判定；无固定绑定且本次无分类要求时省略企业分类字段。

第 5 节按以下列项呈现；没有检查时直接说明原因：

| 检查或命令 | 执行位置/目录或运行身份 | 结果 | 覆盖范围与未覆盖内容 | 证据 |
| --- | --- | --- | --- | --- |

修复验证证据按[收据绑定与失效](core-contracts.md#收据绑定与失效)关联候选、环境和观察时间，共享信息可引用一次。证据定位到文件位置、提交、MR 材料或检查记录；报告复用真实记录，不能替代修改前必须输出的[准入记录](repair-and-verification.md#候选修改前的准入记录)。

将模式特有信息补入记录信息或第 6 节：CI Job 说明实际留下的代码、后续 Patch 提取责任和未覆盖的外层检查；远端验证说明实际专用 ref、候选 SHA、触发方式、Provider 运行身份、最近观察时间及是否仍需观察。流水线状态引用实际观察，不由本地检查推导。

## 交付检查

完成交付前核对：

1. 六个章节齐全，结论、修改和检查对应同一组实际仓库与候选；未知、不适用及未执行项均有说明。
2. 关键结论有可定位证据，重要缺口与未恢复项已披露；要求分类时，初始与最终分类分别列明，最终小类有据或明确标记未完成。修复结果符合既有判据，分类交付、协作提交与整次修复完成分开表达。
3. 文件交付已读回并确认内容属于本次调用，再提供真实路径；纯文字或降级交付已输出完整正文。另有声明产物时确认实际存在；文件交付失败如实披露，保留修复与验证的观察事实。
