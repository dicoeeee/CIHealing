# 文字版结果报告

本文件定义最终报告的填写规则、输出位置与交付检查；固定排版以[报告模板](../assets/analysis-fix.template.md)为唯一来源。报告汇总影响结论的重要事实和尝试，按需引用过程记录；无需复述全部 Attempt 或工具调用。

## 交付时机

本次调用结束时交付报告，包括只读诊断，以及修复成功、未解决、非修复路径、权限不足或限额耗尽。等待用户答复时仅报告当前事实与请求，保留本次调用；子 Agent 移交并结束子任务时交付本次报告，标明整次修复的未完成事项。协作行为与实际提交情况按[交互与移交](execution-modes.md#交互与移交)记录。

输出目录、同名文件保护、校验范围冲突与文件交付失败的处理统一见[报告输出准备](output-delivery.md)。使用文件输出前读取，已核对且仍有效的布局可复用；未提供 `output_dir` 时直接在宿主消息中交付同结构完整报告。

## 固定结构

生成前完整读取唯一[报告模板](../assets/analysis-fix.template.md)，替换全部 `{{REPORT:…}}`。固定一级标题、六章名称/顺序、记录区必需字段，以及适用表格列名和分类初始/最终两行；下方三级标题只组织指南。六章均有实质内容，无修改/未验证/不适用简述原因；章内可用正文、列表、小节、对比表、代码及引用，不强制字段、顺序或篇幅，也不减少证据披露。

记录信息与仓库候选表始终保留，必需字段维持相对顺序，可增有据的时间/场景等行。执行者角色不默认入记录区，影响协作的角色/能力写第 6 节。请求类型为“仅诊断”或“修复”；多仓/候选逐行绑定，后文沿用标识。未知仓库写原因；`work_dir` 不等于源码路径，缺省目录写“不适用：未提供”。仅诊断不要求修复身份/候选。

**绑定 Profile** 展示实际分类标准，复用[可信绑定](failure-classification.md#选择标准与绑定对象)的标识、已知版本和来源，第 2 节引用入口/规则。无固定或可信调用绑定时填“未绑定：Skill 未固定，本次调用未指定”，不扫描/猜测。已指定但不可读、不适用、配置不全或冲突时保留已知标识/来源，标“未应用标准”及原因，未知版本如实注明；不能改称未绑定/已应用。不同对象的 Profile 分别摘要并对应第 2 节。此行不是模型服务、模型配置或 CI Provider，不替代分类两行，报告阶段不改选绑定。

空项区分 **不适用**（无需）、**未知**（应有而无依据）、**未执行**（未做）、**未完成**（已开始但结果不全），均说明原因；不留空/单独破折号/占位符，不编造身份、分类、准入或结果。

**先确定条件表再写正文**：根据任务事实确定模式、各对象分类要求及已声明/实际检查；沿用这组条件填写报告和校验参数，不先写空表后反推要求。

模板中的条件表格与分组按以下规则使用：

- **远端运行表**：`remote_verify` 保留并逐行绑定仓库/候选，未发布/触发也写缺口；其他模式删表及标题，原 CI 证据仍入第 2 节。
- **失败对象块**：单对象可直接行文，多对象按模板“失败对象”三级标题分别组织。固定绑定或可信调用要求分类时，保留初始/最终两行、Profile、变化及完成度；配置缺口、不可读、不适用、未匹配或小类待定不取消要求，如实标未应用/待定/未完成。仅既无绑定也无本次分类要求时，删除分类专用内容并说明依据。
- **修改说明**：本次、继承或需说明的原有修改，逐文件交代归属、作用、交付状态；表格可改列表/正文，不用则删表，无修改写原因。清理/恢复可合并。
- **检查表**：有已声明或已执行检查则保留，必要但未执行也列行；可按仓库/候选/范围拆表，列名/顺序一致且绑定明确，不漏必需项。既无计划也无执行则删表并说明，不留下空表或虚构检查行。适用工作空间校验及缺口可写表内或正文。

多行日志/代码放表外并关联位置；单元格内包括行内代码的 `|` 写为 `\|`。模板只管呈现，不改变分类、准入、验证或结果判据。

### 1. 处理结论

当前结论、一句话说明和本次调用是否结束。修复调用沿用[结果判定](repair-and-verification.md#结果判定)；仅诊断写明“仅诊断，未执行修复”，不套用修复终局结果。

### 2. 失败与根因

原始失败任务或命令、关键报错、根因判断及证据；区分观察事实、受支持的判断和未确认部分。

- **CI 证据**：引用实际 Provider（或未知）、run/Job/重试身份、本地/MCP/CLI 来源与日志完整性。复用已有快照和访问记录；读取失败不等于原始 CI 失败的根因。
- **日志片段**：按[引用与读取局限](failure-evidence-extraction.md#引用与读取局限)标注原始位置及影响结论的缺口，引用已核对的原文与观察，不复制提取 JSON 全文。
- **分类情况**：对本次要求分类的对象，复用[初始分类与最终分类](failure-classification.md#初始分类与最终分类)记录，交代实际 Profile 标识、版本、入口及绑定来源，并使用模板分类表。初始分类保留首次路径、当时判据和证据，允许没有小类；最终分类填写复核的小类及父级路径、当前判据和证据，无法确定时保留真实判断并标注未完成。初始记录缺失如实说明，不用最终结果倒填。

无变化也保留初始和最终两行，在表内或表后说明分类变化及原因，以及最终分类交付已完成还是未完成。分类完成度和修复结果按[分类与修复边界](failure-classification.md#分类与修复边界)分别判定；分类修正所影响的准入和验证分别在第 3、5 节体现。

### 3. 目标行为与修复依据

目标行为及来源、所选方向与约束、重要相反方向的取舍或仍需的区分性证据。修复调用引用实际已有的准入记录，报告最终复核结论及重要反证的处置；尚未形成准入时如实注明。最终报告不能替代修改前必须输出的[准入记录](repair-and-verification.md#候选修改前的准入记录)。

修复调用复用[策略记录](enterprise-policy.md#判断与行动)，未配置时简记；其实际判断应与结论、修改/恢复及交接一致，不在报告阶段另行放行。仅诊断可引用已核对的策略事实，不因此进入修复准入。

### 4. 实际修改

列明文件、修改及作用，区分用户/Job 原有内容、继承候选和本次修改；说明交付时保留、已恢复和未恢复的内容。未修改时说明原因。

需要[工作空间清理与校验](workspace-cleanup.md)时，在此记录实际删除/恢复及保留依据。CI Job 还须明确实际留在指定工作空间的代码；后续 Patch 提取责任写入第 6 节。

### 5. 验证结果

按模板检查表逐项列检查、实际结果、覆盖范围和证据；必要检查未执行或未完成时说明原因。区分本次检查、原始失败与复用的历史证据。没有检查时按上述裁剪规则说明原因，不创建虚构的验证行。

修复验证证据按[收据绑定与失效](core-contracts.md#收据绑定与失效)关联候选、环境和观察时间；证据定位到文件位置、提交、MR 材料或检查记录。流水线状态引用实际观察，不由本地检查推导。

适用工作空间校验时，列实际根、清单/原摘要、调用/候选绑定、最新结论与时间，与编译结果分开；应做但未采集/未完成也披露。不复制全清单，不把 `match` 扩展为无历史冗余、Patch 已提取或修复正确。最新有效结果为 `mismatch`/`incomplete` 或缺失时，即使差异已解释、编译通过，也按[清理出口](workspace-cleanup.md#结束与协作)记录未完成，不称清理/整体通过。

基准缺失/时序错误保留历史事实；若已按[恢复路径](workspace-recovery.md#基准缺失或时序错误的恢复)纠正，说明重建依据、新基准、重验和最终校验，按实际条件判定交付，不改写为首次合规。

### 6. 剩余问题与交接

说明缺口、影响及继续所需的信息、权限或检查；协作时列接收方、具体请求、实际提交情况和未完成事项。“无剩余项”仅指本次任务与验证范围。按本次实际情况补充：

- CI 访问能力缺口、已尝试路径及继续所需条件。
- 未确定小类、未匹配、标准未应用或初始记录缺失等分类交付缺口及影响。
- 清理残留、读取缺口、范围外或历史产物问题，以及未恢复项。
- 原生 clean 的执行或跳过原因、本次独立目录和临时产物的回收收据、必要保留项及证据完整性。源码一致、进程退出和文件回收分别说明，不以任一通过代替另两项。
- CI Job 的后续 Patch 提取责任和未覆盖的外层检查；远端验证是否仍需观察及实际续接条件。

## 交付检查

1. 按任务条件裁剪模板，填入已复核事实；结论、修改、检查绑定同组仓库/候选。
2. 写入最终正文并停止编辑后，可在**同一轮**调用[格式校验](#格式校验)与只读读回。两者须覆盖同一份最终字节，核对校验收据绑定的正文与读回一致，不省略任一动作。任何修改都使这两项旧结果失效，须重新校验并读回；不得与报告写入并行。
3. 据实际结果复核关键结论、证据、反证、缺口及未恢复项；有分类要求时按[分类标准边界](failure-classification.md#分类标准边界)核对 Profile、路径、判据与证据，最终小类有据或明确未完成。分类完成、协作提交和整次修复完成分别表达，发现实质问题须纠正或披露。
4. 确认报告属于本次调用、其他声明产物实际存在，再交付真实绝对路径；最后消息只需结论摘要、关键缺口和路径，不重述报告/诊断。纯文字或降级交付完整同结构正文；文件失败披露原因，保留实际修复/验证观察，不声称规范交付完成。

### 格式校验

通过宿主指定脚本工具执行 [scripts/report_check.py](../scripts/report_check.py)（Python 3.9+、标准库），参数以 `--help` 为准。脚本只读模板和报告，不改文件、不执行正文命令、不访问引用证据。以下有序参数替换实际路径：

```json
["--report", "/approved/output_dir/analysis-fix.md",
 "--classification", "required", "--checks", "present"]
```

两项参数由任务事实确定，不能按报告漏写内容反推：

- `--classification`：全对象有要求为 `required`，全无为 `none`，部分有为 `mixed`。标准不可用/不适用不取消已有要求；Agent 核对对象绑定，脚本只查分组表格与格式。
- `--checks`：有声明或实际检查为 `present`，包括必需但未执行；均无才用 `none`。

脚本检查固定标题/章节、记录区必需项、适用表/列数、分类两行、占位符和文件名，不约束章内标签、顺序或风格。JSON 绑定正文 SHA-256：`valid`/0 表示结构通过，`invalid`/1 列定位问题，`incomplete`/2 表示输入、模板或读取不足。不验证 Profile 类别合法性、证据真实性、语义完整性或修复正确性，不能替代事实复核。

纯文字或文件交付失败时，可将完整正文通过标准输入传给 `--report -`，无需新增文件；传输须保留正文原样并避免 shell 展开其中的命令。宿主不支持安全传入正文、Python/脚本不可用或读取失败时，对照模板检查后照常交付，并在第 6 节说明格式校验未完成及原因。格式错误由 Agent 修正；无法在本次限额内修正时如实交付现有事实并披露格式缺口，不声称规范交付已完成。

格式检查收据留在宿主输出即可，不新增必交文件。若需说明校验缺口，在第 6 节记录；格式检查不作为 CI 构建验证，也不改变修复结果。Skill 文本要求执行检查，但不能保证工具调用不被跳过；需要强制交付门槛时由宿主落实。
