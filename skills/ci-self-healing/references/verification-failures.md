# 失败后的处理

本指南由主入口[执行异常](../SKILL.md#执行异常)在取证、诊断实验或候选验证阶段按需安排，判断失败影响并交回局部处置结果，不以已有候选为前提。转人工案例访问失败的局部停止条件由有限检索流程定义，不适用本文的替代或重试规则；其他专用异常也沿用入口安排的对应规则。本文不改变请求类型、行动范围、授权、调用预算或成功标准。

按当前动作的实际目标判断是否发生执行异常：原始 CI 失败日志、搜索正常返回无结果，以及诊断实验按计划取得的失败现象，均可作为正常证据处理，不仅凭非零退出码或文本含 error 触发本指南。候选复验未达到通过条件仍是验证失败；工具不可用、超时或所需结果不完整时记录实际缺口。

## 失败后的路径选择

区分原 CI、候选验证与工具执行失败，保留当前步骤、实际结果及证据；有候选时关联候选身份。结合已有差异、依赖、基线与实际结果，判断新失败为 related/unrelated/uncertain 并说明与当前问题或候选的关系；没有候选时不为处理取证失败创建候选或补填候选字段。多阻塞分别判断，不要求遍历所有路径。

一次验证失败不自动满足案例触发判据。已有只读建议范围不允许本指南授予新的候选或验证动作；受阻检索的工具替代仅用于只读补证。已有恢复及必要校验义务保持。

| 当前证据 | 局部处置与需要记录的影响 |
| --- | --- |
| 取证工具不可用、超时或响应不全 | 复用有效材料；CI 平台取证按Provider 访问，历史案例按案例 MCP/CLI 访问，其他取证仅使用原已授权入口。不重做全部取证；记录有无获准替代及缺口影响，不换工具绕过拒绝 |
| 验证反驳候选或关键前提 | 记录反证及受影响判断，旧准入不能用于相关写入；已决定放弃的候选按恢复规则恢复/核对，记录残留与恢复缺口，不叠加新候选 |
| 环境、工具或无关失败阻断验证，候选未被判定 | 保留有据候选/真实结果，在既有模式/授权内寻找满足同一要求的路径；无法完成则报告缺口，不删检查、降条件或因本地缺环境转远端发布 |
| 新证据造成目标/方向关键歧义 | 暂停相关修改/发布，记录不同解释、所缺区分性证据及其影响，不换候选试绿代替意图判断 |
| 策略禁止、必要授权被拒或适用性未决 | 暂停受限动作，按企业策略记录限制、适用性与缺口；不借换工具、Agent 或重试绕过 |

发布/触发结果不明先远端核对，不按普通失败重试；恢复不安全则暂停相关写入，不叠加被放弃候选残留。

Fallback 仅限既有授权、有据替代或有界重试，记录缺口和新结果，不机械重复无新信息动作，不重置本次调用身份/预算。一次工具失败不证明原问题是非修复路径。

## 交回条件

在已有诊断或执行记录中说明失败发生的步骤与对象、对证据和适用候选/收据有效性的影响、已采取的局部处置及剩余缺口；无候选时只记录相关取证影响。可用替代、无法继续或处理失败都应有实际依据，不以问题必须解决作为本指南的结束条件。交回主入口，由发生异常阶段按原有继续或停止条件推进，不新增表单、状态文件或下一阶段的加载指令。
