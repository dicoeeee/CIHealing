# 失败后的处理

仅在取证工具、实验或候选验证实际失败后，决定后续动作前读取；原 CI 失败本身不要求加载。本文不改变授权、调用预算或成功标准。

## 失败后的路径选择

区分原 CI、候选验证与工具执行失败，保留步骤、结果、候选身份及证据。结合差异、依赖、基线与实际结果判断新失败为 related/unrelated/uncertain 并说明依据，再按表选择；多阻塞分别处理，不要求遍历所有路径。

一次验证失败不自动触发案例检索；仍有有效现场线索时继续原诊断，确认受阻后才按[案例触发条件](diagnosis-and-repair.md#路由通用与企业知识)判断。已转建议时，下表重新准入下一候选、补候选验证等路径不再适用，工具替代仅用于只读补证；已有恢复、清理及必要校验仍须完成。

| 当前证据 | 下一步与停止条件 |
| --- | --- |
| 取证工具不可用、超时或响应不全 | 复用有效材料；CI 平台取证按[Provider 访问](providers/provider-access.md#选择访问方式)，历史案例按[案例 MCP/CLI 访问](case-retrieval.md#mcp-与-cli-访问)，其他取证沿原已授权入口补缺口。不重做全部取证；无获准替代且影响判断则协作/结束，不换工具绕过拒绝 |
| 验证反驳候选或关键前提 | 更新诊断、撤销受影响准入；放弃候选先按[恢复规则](execution-modes.md#基线与候选恢复)恢复/核对，再在有据新策略及预算内重新准入下一候选；无进展则结束 |
| 环境、工具或无关失败阻断验证，候选未被判定 | 保留有据候选/真实结果，在既有模式/授权内寻找满足同一要求的路径；无法完成则报告缺口，不删检查、降条件或因本地缺环境转远端发布 |
| 新证据造成目标/方向关键歧义 | 暂停相关修改/发布，按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)补区分性证据；未解则澄清/移交/结束，不换候选试绿代替意图判断 |
| 策略禁止、必要授权被拒或适用性未决 | 暂停受限动作，记录限制与缺口；需要协作时按[交互与移交](collaboration.md#交互与移交)，修复调用另按[企业策略](enterprise-policy.md#判断与行动)处理；不借换工具、Agent 或重试绕过 |

发布/触发结果不明先[远端核对](remote-verification.md#外部动作结果不明时)，不按普通失败重试；恢复不安全则暂停相关写入，不叠加被放弃候选残留。

Fallback 仅限既有授权、有据替代或有界重试，记录缺口和新结果，不机械重复无新信息动作，不重置本次调用身份/预算。协作按[交互与移交](collaboration.md#交互与移交)区分只读与修复分支；只读诊断按[文字版结果报告](result-report.md)交付，修复调用继续遵守[调用限额](core-contracts.md#调用身份与限额)并按[结果判定](repair-and-verification.md#结果判定)结束。一次工具失败不证明原问题是非修复路径。
