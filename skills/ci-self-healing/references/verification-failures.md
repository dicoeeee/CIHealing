# 失败后的处理

本指南判断取证工具、实验或候选验证失败的影响，并定义相应局部处置；原 CI 失败本身不要求加载。转人工案例访问失败的局部停止条件由[有限检索流程](case-retrieval.md#转人工前的检索流程)定义，不适用本文的替代或重试规则。本文不改变授权、调用预算或成功标准；跨阶段选择由主入口安排。

## 失败后的路径选择

区分原 CI、候选验证与工具执行失败，保留步骤、结果、候选身份及证据。结合差异、依赖、基线与实际结果判断新失败为 related/unrelated/uncertain 并说明依据；多阻塞分别判断，不要求遍历所有路径。

一次验证失败不自动满足[案例触发判据](diagnosis-and-repair.md#路由通用与企业知识)。已有只读建议范围不允许本指南授予新的候选或验证动作；受阻检索的工具替代仅用于只读补证。已有恢复、清理及必要校验义务保持。

| 当前证据 | 局部处置与需要记录的影响 |
| --- | --- |
| 取证工具不可用、超时或响应不全 | 复用有效材料；CI 平台取证按[Provider 访问](providers/provider-access.md#选择访问方式)，历史案例按[案例 MCP/CLI 访问](case-retrieval.md#mcp-与-cli-访问)，其他取证仅使用原已授权入口。不重做全部取证；记录有无获准替代及缺口影响，不换工具绕过拒绝 |
| 验证反驳候选或关键前提 | 记录反证及受影响判断，旧准入不能用于相关写入；已决定放弃的候选按[恢复规则](execution-modes.md#基线与候选恢复)恢复/核对，记录残留与恢复缺口，不叠加新候选 |
| 环境、工具或无关失败阻断验证，候选未被判定 | 保留有据候选/真实结果，在既有模式/授权内寻找满足同一要求的路径；无法完成则报告缺口，不删检查、降条件或因本地缺环境转远端发布 |
| 新证据造成目标/方向关键歧义 | 暂停相关修改/发布，记录不同解释、所缺区分性证据及其影响，不换候选试绿代替意图判断 |
| 策略禁止、必要授权被拒或适用性未决 | 暂停受限动作，按[企业策略](enterprise-policy.md#判断与行动)记录限制、适用性与缺口；不借换工具、Agent 或重试绕过 |

发布/触发结果不明先[远端核对](remote-verification.md#外部动作结果不明时)，不按普通失败重试；恢复不安全则暂停相关写入，不叠加被放弃候选残留。

Fallback 仅限既有授权、有据替代或有界重试，记录缺口和新结果，不机械重复无新信息动作，不重置本次调用身份/预算。本任务的结果包括失败归属、候选与收据是否仍有效、已采取的局部处置及剩余缺口；一次工具失败不证明原问题是非修复路径。
