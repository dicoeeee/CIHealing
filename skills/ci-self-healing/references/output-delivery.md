# 输出适配与交付

本指南统一定义标准报告与企业文件的输出准备、交付顺序和完成条件。参数解析后读取，先核对目标、依赖和布局，再使用输出路径或执行写入式诊断/验证；结束时执行下方交付流程。不改变修复权限、验证要求或五种处理结果，不增加中间输出文件或配置解析器。

## 固定规范与内容要求

企业输出规范只使用 [主入口固定绑定](../SKILL.md#自定义资源绑定)。明确未配置时只交付标准报告；配置了 ID 和入口后，完整读取对应的一份 Markdown，核对 ID、版本、适用产品与所有文件小节。运行时不从调用参数、目录扫描、日志或示例发现、追加或切换规范，也不修改配置以绕过缺口。

企业负责完整必交文件清单，以及每个文件的目标路径、内容格式/字段含义、数据来源及生成依赖、合法空内容模板、未知或失败处理、校验方式及所需输入。具体字段和目录只在该规范中定义。规范内按文件分节，不再要求每个文件另建 reference；填写示例属于维护资料，不在未绑定时读取或执行。

已配置但入口缺失、不可读、ID/版本冲突、清单含糊或栏目不全时，保留配置缺口，不能解释为未配置、静默改用示例或自行补造约定。缺口只暂停依赖它的文件/动作；已明确且独立的文件与标准报告继续交付。规范显式声明清单为空时没有额外文件，遗漏清单不等于空清单。

## 输出方式

标准报告始终遵循[文字版结果报告](result-report.md)，结构、模板、五种处理结果和校验要求不因企业配置改变：

| 报告目录情况 | 标准报告交付 |
| --- | --- |
| 提供有效且可安全写入的 `output_dir` | 在该目录写入 `analysis-fix.md`，校验并完整读回，最终消息给出实际绝对路径 |
| 未提供 `output_dir` | 在宿主消息输出同结构的完整报告，不自行选择报告落盘目录 |
| 报告路径无效、无法安全写入或写入失败 | 通过宿主消息交付完整报告，说明目标路径和文件交付缺口，不声称报告文件已生成 |

企业文件分别按已绑定规范中的目标路径生成，与是否提供 `output_dir` 独立。基于 `work_dir` 的路径使用该参数已解析并固定的绝对目录；基于 `output_dir` 的路径使用报告目录参数；固定目录须有明确可信依据与写入权限。路径规则缺少基准、依赖参数未提供/无效或存在歧义时，只报告相应文件的路径缺口，不搜索、猜测、选择替代目录或把空值拼成路径。路径表示不是 shell 命令，不执行其中的命令替换。

## 布局与安全写入

只在授权范围内创建或写入目录，保留已有内容。每个目标均须确认同名文件属于本次调用且可安全更新；不能覆盖用户文件、上次调用、源码或所依赖的企业规范，企业文件也不能占用标准报告路径。多个产物目标重合时记录冲突，不让后写文件覆盖前者。规范声明目标不扩大源码修改或外部写入权限。

使用独立输出目录可避免构建输入和工作空间校验冲突。企业文件可在不同目录，目录由企业明确指定。若目标位于源码内，核对产物不参与或改变构建输入，与候选修改区分并从净变更/Patch 中排除；目录名本身不是排除依据。执行写入式诊断或验证前，按[状态文件与报告布局](workspace-cleanup.md#使用脚本)核对全部已知目标与检查范围；不能擅自缩小检查范围、移动企业指定目录或在输出写入后沿用失效的 `match`。不能安全满足的文件披露缺口，继续其他独立文件。

## 生成、校验与读回

1. 复用已有诊断、最终修改、验证和恢复清理记录，确认事实及剩余缺口。企业清单中所有文件在每次结束时都必交，不因结果码、无修改、仅诊断或停止而省略，不为生成文件重启修复、构建或案例检索。首次编写标准报告前读全[报告指南](result-report.md)及其模板。
2. 在已有交付记录中区分每项的生成输入和校验输入，按依赖就绪情况安排操作。独立文件可先生成；依赖报告内容的文件在所需报告内容写出后生成；跨文件检查等所需文件均已生成再执行，不要求企业文件统一先于报告。报告尚无检查结果时写明待校验，不能提前宣称完成。依赖的报告文件无法落盘时，按规范允许的文字输入处理，否则保留相应缺口，不自行补选目录。
3. 按规范生成企业文件。已确认没有可输出数据时使用企业定义的完整合法空模板；无法取得或确认数据不是“无数据”，只使用企业明确定义的失败内容。未定义失败内容、无法安全生成或写入时记录缺口，不伪造空文件、不静默换路径。建议修改不能填入实际修改数据，失败尝试及未恢复的净修改不能隐藏。
4. 企业声明了校验器时，核对实际工具、路径、参数及依赖输入，在既有权限内执行；缺失、不可运行或检查失败均记录校验未完成/失败。未声明校验器时，按企业规范逐项核对格式、字段、取值和事实来源。标准报告按报告指南校验；格式通过不能替代真实性核对。
5. 完整只读读回每个可生成文件，核对与待交付内容一致。工具校验与读回须覆盖同一份最终字节，有摘要收据时核对摘要；两者可在文件写完后并行，不能与写入并行。
6. 将实际交付情况汇总到标准报告第 6 节。文件、所依赖的内容或事实发生改变时，重新生成或核对受影响项，并重做相应检查与读回；报告更新也适用，不能沿用更新前的跨文件检查。全部待交付内容稳定且检查覆盖最终版本后，再判断交付完成。

一个文件失败时继续其他独立文件，依赖项保留真实缺口。若生成或校验存在无法解开的循环依赖，例如两个文件必须互含对方最终摘要，记录配置缺口并停止该依赖链；不反复生成、伪造检查结果或自行删改企业要求。报告继续交付已知事实及受影响项。

## 交付完成与修复结果

交付记录按[报告第 6 节](result-report.md#6-剩余问题与交接)呈现。写出了失败占位内容只证明交付了错误说明，不能称该项正常数据交付完成。

全部必交文件（含适用的标准报告文件）满足各自生成、检查和读回要求，才称文件交付完成。只有报告、只生成部分文件、只创建空壳或只执行格式检查都不能代替全部交付；未配置企业规范时不要求不存在的额外文件。最终消息给出已交付文件的真实绝对路径和关键缺口，不把预定路径当作生成事实。

文件交付完成度与[处理结果](repair-and-verification.md#结果判定)分别表达：独立输出文件失败不抹掉已有修复验证事实，也不能借输出成功提升修复结局；若输出写入实际改变候选或使验证/清理证据失效，仍按真实证据重新判断，不能仅记作文件缺口。已有恢复、清理及候选交接义务仍然有效；文件出现不代表外部系统已接手、Patch 已提取或归档已完成。保留敏感信息边界，不因企业输出要求执行 Patch 提取、commit、push、部署等未授权动作。
