# 输出适配与交付

本指南统一定义报告适用范围、企业输出准备、交付顺序和完成条件。参数解析后读取，核对目标、依赖和布局，再使用输出路径或执行写入式诊断/验证；结束时执行下方交付流程。输出要求不改变修复权限或验证要求，不增加中间输出文件或配置解析器。

## 报告适用范围

正式六章报告 `analysis-fix.md` 只用于修复请求同时明确提供 `work_dir` 和 `output_dir` 的 [CI Job 失败现场目录](ci-job-failure-directory.md)场景，执行模式为 `local_verify`。按参数实际提供情况确定范围，不从最终报告内容反推；参数已提供但无效，仍须交付已知事实的正式报告，输入或写入缺口只影响相应动作。

其他调用，包括仅诊断、单参数、未提供参数和通用远端验证，直接用普通回复交代结论、实际操作、证据限度及下一步，不自动套用正式报告、模板或三种处理结果。用户明确追加的交付要求按其授权范围处理，不通过伪造请求类型或模式通过本报告校验。

企业文件由固定规范独立约定，不受是否生成正式报告影响。未提供 `output_dir` 仍须处理基于有效 `work_dir` 或已授权固定目录的企业文件。

## 固定规范与内容要求

企业输出规范只使用 [主入口固定绑定](../SKILL.md#自定义资源绑定)。明确未配置时无额外文件要求；配置了 ID 和入口后，完整读取对应的一份 Markdown，核对 ID、版本、适用产品与所有文件小节。运行时不从调用参数、目录扫描、日志或示例发现、追加或切换规范，也不修改配置以绕过缺口。

企业负责完整必交文件清单，以及每个文件的目标路径、内容格式/字段含义、数据来源及生成依赖、合法空内容模板、未知或失败处理、校验方式及所需输入。具体字段和目录只在该规范中定义。规范内按文件分节，不再要求每个文件另建 reference；填写示例属于维护资料，不在未绑定时读取或执行。

已配置但入口缺失、不可读、ID/版本冲突、清单含糊或栏目不全时，保留配置缺口，不解释为未配置、不改用示例或补造约定。缺口只暂停依赖它的文件/动作；独立文件及本次结果说明继续交付。规范显式声明清单为空时没有额外文件，遗漏清单不等于空清单。

## 输出方式

先按上述范围确定是否需要正式报告，再选择交付方式：

| 调用与目录情况 | 结果交付 |
| --- | --- |
| 双参数流水线修复，`output_dir` 可安全写入 | 按[报告指南](result-report.md)写入 `analysis-fix.md`，校验并完整读回 |
| 双参数流水线修复，参数无效、路径不安全或写入失败 | 在宿主消息交付同结构完整报告，说明输入/文件缺口；可用标准输入校验正文，不声称报告文件已生成 |
| 其他调用 | 普通回复交付结论与实际交付记录，不自行生成正式报告或另选落盘目录 |

企业文件按已绑定规范的目标路径生成。基于 `work_dir` 的路径使用该参数已解析并固定的绝对目录；基于 `output_dir` 的路径使用其解析结果；固定目录须有明确可信依据与写入权限。缺基准、依赖参数未提供/无效或有歧义时，只报告相应文件的路径缺口，不搜索、猜测或选择替代目录。路径表示不是 shell 命令，不执行其中的命令替换。

## 布局与安全写入

只在授权范围内创建或写入目录，保留已有内容。每个目标均须确认同名文件属于本次调用且可安全更新；不能覆盖用户文件、上次调用、源码或所依赖的企业规范，企业文件也不能占用本次正式报告路径。多个目标重合时记录冲突，不让后写文件覆盖前者。规范声明不扩大源码修改或外部写入权限。

使用独立输出目录可避免构建输入和工作空间校验冲突。企业文件可在不同目录，由企业明确指定。若目标位于源码内，核对产物不参与或改变构建输入，与候选修改区分并从净变更/Patch 中排除；目录名本身不是排除依据。执行写入式诊断或验证前，按[状态文件与报告布局](workspace-cleanup.md#使用脚本)核对已知目标与检查范围；不能缩小检查范围、移动企业指定目录或在输出写入后沿用失效的 `match`。不能安全满足的文件披露缺口，继续独立文件。

## 生成、校验与读回

1. 复用已有诊断、最终修改、验证和恢复清理记录。企业清单中所有文件在每次结束时都必交，不因结果码、无修改、仅诊断或停止而省略，不为输出重启修复、构建或案例检索。需要正式报告时，首次编写前读全[报告指南](result-report.md)及模板。
2. 在已有记录中区分生成输入和校验输入，按依赖就绪情况安排操作。独立文件可先生成；依赖报告内容的文件等相应内容写出后生成；跨文件检查等所需文件均已生成再执行。报告尚无检查结果时注明待校验。若本次不生成正式报告或无法落盘，依赖它的文件按规范允许的文字输入处理，否则保留依赖缺口，不自行扩大报告范围或补选目录。
3. 按规范生成企业文件。已确认无数据时使用企业完整合法空模板；未知不是无数据，只使用企业明确定义的失败内容。未定义失败内容、无法安全生成或写入时记录缺口，不伪造空文件。建议修改不能填入实际修改数据，失败尝试及未恢复的净修改不能隐藏。
4. 声明了企业校验器时，核对实际工具、路径、参数和依赖输入，在既有权限内执行；缺失、不可运行或检查失败均记录未完成/失败。无校验器时按规范逐项核对格式、字段、取值和事实来源。正式报告按报告指南校验；格式通过不替代真实性核对。
5. 完整只读读回每个可生成文件，核对待交付内容。校验与读回覆盖同一份最终字节，有摘要收据时核对摘要；两者可在写完后并行，不能与写入并行。
6. 正式报告在第 6 节汇总实际交付记录，其他调用在普通回复中汇总。文件、依赖内容或事实改变后，重新生成或核对受影响项，并重做检查与读回；报告更新同样使相关旧检查失效。待交付内容稳定且检查覆盖最终版本后，再判断完成。

一个文件失败时继续独立文件，依赖项保留缺口。无法解开的循环依赖，例如两个文件必须互含对方最终摘要，记作配置缺口并停止该依赖链；不反复生成、伪造结果或删改企业要求。本次结果说明仍交付已知事实及受影响项。

## 交付完成与修复结果

交付记录列规范 ID/版本/入口或未配置，逐项列目标/实际路径、生成、校验或规范核对、完整读回及缺口；有正式报告时按[第 6 节](result-report.md#6-剩余问题与交接)呈现。失败占位内容只证明交付了错误说明，不能称正常数据已交付。

全部必交文件（含适用的正式报告文件）满足各自生成、检查和读回要求，才称文件交付完成。部分文件、空壳或仅格式通过不能代替全部交付；不要求本次范围之外的报告或未配置的企业文件。最终回复给出真实绝对路径与关键缺口，不把预定路径当作生成事实。

文件交付与修复成果分别表达：独立输出失败不抹掉已有修复验证事实；输出成功不提升修复结局。若写入实际改变候选或使验证/清理证据失效，仍按真实证据重评。已有恢复清理及交接义务有效；文件出现不代表外部系统接手、Patch 提取或归档完成。保留敏感信息边界，不因输出要求执行未授权的 Patch 提取、commit、push 或部署。
