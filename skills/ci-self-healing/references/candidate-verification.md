# 候选实施与分层验证

准备形成候选及其验证计划时完整读取，首次候选修改或构建/验证前须读完适用规则；已读且仍适用则复用。只读停止分支不加载。本文不授予准入，写入式实验仅在自身准入范围内执行检查，不因此成为候选；沿用已确认的准入与企业策略，不重新授予权限。

## 构建与更新候选

依据已记录的决定实施候选，保留与其对应的修复依据及验证计划。候选指相对于介入时工作空间的完整修改集合，恢复和修改归属统一遵循 [执行模式](execution-modes.md#基线与候选恢复)，不额外要求生成 Patch 文件。

在符合目标与约束的方案中选影响较小的修改，综合比较依赖影响、行为变化、额外机制、运行时处理与维护负担，不以文件数或增删行数单独判断。测试、断言、策略或检查只有在当前意图和证据表明它们本身错误时才应调整，不以压制失败作为修复目的。

## 分层验证

| 层级 | 目的 |
| --- | --- |
| V0 Candidate Guard | 检查基线、实际差异、路径、策略、语法、Schema 和候选身份 |
| V1 Root Failure | 通过当前有效入口复验原失败目标及其验收要求 |
| V2 Affected Scope | 运行受影响测试、调用方、依赖检查、配置验证或 dry-run |
| V3 Broader Scope | 在已声明或确有必要时，运行更广的回归或下游检查 |
| V4 Outer CI | 观察准确发布候选对应的宿主流水线或 Required Checks |

V1 以原失败目标、配置及验收范围为基准，通常重跑原命令/任务/PoC/检查。获准修正构建规则、参数或入口后，按当前项目配置生成有效动作，记录变化依据及与原目标的对应；不机械重放失效命令，也不临时手改命令绕过配置、跳过阶段、缩小验收或降低条件。局部检查不替代 V1，无法完成则记录缺口。

`required_verification` 逐项列检查标识、层级、命令或 Job/Check、位置（`local`/`remote`）、是否必须发布前完成及通过条件。V0 与仓库/Harness 声明的发布前本地检查必须先于发布；位置选择不减少要求。

参数去留、值传递、接口行为或配置含义的修复，V2 须含能检验该决定的针对性检查；共享接口覆盖调用方兼容性。预期来自已确认目标/契约，不能由候选反推；独立遗留问题按实际关联判断是否影响必要验证。

V1/V2/适用 V3 可由 V4 具体任务承担，无需本地重复，但逐项映射准确候选。收据按核心合同绑定位置、命令/任务、结果和未执行/未完成原因：本地未执行记 `not_run` 并说明远端承担项，启动未完成记 `incomplete`；远端通过不改写本地事实或抹去失败，本地通过只证明预检范围。

会写源码工作空间的诊断、构建或验证，执行前读取[清理与校验](workspace-cleanup.md)，将工作空间校验列为必需检查，与构建结果分别记录；成功与缺口出口见其[结束与协作](workspace-cleanup.md#结束与协作)。
