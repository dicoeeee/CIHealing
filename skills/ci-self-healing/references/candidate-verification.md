## 构建与更新候选

依据已记录的决定实施候选，保留与其对应的修复依据及验证计划。候选指相对于介入时工作空间的完整修改集合，恢复和修改归属统一遵循 执行模式，不额外要求生成 Patch 文件。

在符合目标与约束的方案中选影响较小的修改，综合比较依赖影响、行为变化、额外机制、运行时处理与维护负担，不以文件数或增删行数单独判断。测试、断言、策略或检查只有在当前意图和证据表明它们本身错误时才应调整，不以压制失败作为修复目的。

## 分层验证

### 选择本地执行范围

先复用与当前代码状态、必要输入和检查目标对应且仍有效的执行记录，只对关键缺口或失效检查执行补证。确需执行本地诊断实验或候选验证时，从已绑定的失败记录及项目脚本核对实际失败命令，区分失败子命令与仅汇总失败的外层入口；保留所需工作目录、参数、环境、输入和前置步骤，选择能够覆盖检查目标与验收条件的最小可独立执行单元。

能够等价复验失败子命令时，须在该层执行，不因外层脚本是 CI 入口就重跑全流程。仅当前置条件无法可靠分离、修改涉及外层编排、变更影响或明确验收要求需要更广检查时，扩大到足够覆盖的范围。执行前在已有计划或调用说明中简述命令与检查目标的对应，扩大时说明依据，不新增文件或固定表单。

例如 `build.sh` 中的 `npm install` 失败，所需准备仍有效且该命令覆盖原失败目标时，按原目录、参数和环境执行 `npm install`；若修改了脚本向它传参或准备输入的逻辑，则验证覆盖该逻辑的入口。子命令通过后不自动追加完整脚本，后续检查由修改影响和验收要求决定。此规则不授权删减远端 CI 的 Job/Check。

### 验证层级

| 层级 | 目的 |
| --- | --- |
| V0 候选基础检查 | 核对 Git 来源、候选实际差异、路径、策略、语法、Schema 和候选身份 |
| V1 原失败复验 | 通过当前有效的最小执行单元或指定远端任务复验原失败目标及其验收要求 |
| V2 受影响范围验证 | 运行受影响测试、调用方、依赖检查、配置验证或 dry-run |
| V3 更广范围验证 | 在已声明或确有必要时，运行更广的回归或下游检查 |
| V4 外层 CI 验证 | 观察准确发布候选对应的宿主流水线或 Required Checks |

V1 以原失败目标、配置及验收范围为基准；保留必要上下文且覆盖该目标的等价子命令可以完成 V1，无需再执行仅包裹它的外层流程。获准修正构建规则、参数或入口后，验证当前项目配置生成的有效动作，记录变化依据及与原目标的对应；不机械重放失效命令，也不临时手改命令绕过待验证的配置或必要前置阶段。仅覆盖部分目标、跳过必要检查或降低条件的局部检查不能替代 V1，无法完成则记录缺口。

必要检查不能因未列入计划而被省略。`required_verification` 逐项列检查标识、层级、命令或 Job/Check、位置（`local`/`remote`）、是否必须发布前完成及通过条件。V0 与仓库/Harness 声明的发布前本地检查必须先于发布；位置选择不减少要求。

参数去留、值传递、接口行为或配置含义的修复，V2 须含能检验该决定的针对性检查；共享接口覆盖调用方兼容性。预期来自已确认目标/契约，不能由候选反推；独立遗留问题按实际关联判断是否影响必要验证。

V1/V2/适用 V3 可由 V4 具体任务承担，无需本地重复，但逐项映射准确候选。收据按核心合同绑定位置、命令/任务、结果和未执行/未完成原因：本地未执行记 `not_run` 并说明远端承担项，启动未完成记 `incomplete`；远端通过不改写本地事实或抹去失败，本地通过只证明预检范围。

验证计划绑定完整实际候选及必要输入；复用已有候选 fingerprint 与修改记录。验证后按执行模式中的候选与验证有效性规则核对最终交付内容。仅影响候选或检查有效性的变化使相应收据失效，不因普通编译产物保留、新增空目录或未执行产物清理而重验。

## 完整成功条件


本节的验证与证据要求适用于所有修复调用；仅双参数流水线内修复报告将本地成功记为 `local_verified`。层级判据沿用本文件的[分层验证](#分层验证)：V0 为候选基础检查，V1 为原失败复验，V2 为受影响范围验证，V3 为必要的更广回归，V4 为准确发布候选对应的外层 CI。

- `local_verify`：V0、V1 和全部必要的 V2/V3 在当前工作空间环境实际通过。
- `remote_verify`：V0 与发布前检查先通过；V1、必要 V2/V3 在计划指定位置实际通过，准确候选对应的 V4 通过。远端任务可承担对应检查，不要求本地重复；远端事实按远端验证交付，不使用流水线报告或将部分本地检查称为完整成功。

宣告成功前按完整实际修改复核修复依据、准入、原记非阻塞的未知项、重要反证及证据有效性，保留结论和引用。候选必须符合有据的目标行为，无未决语义方向或其他关键缺口，最终候选仍受有效验证覆盖，需撤销的修改已安全恢复。准入、语义依据和必要验证各自成立，编译或 CI 通过不能替代其他条件。

必要检查不得通过漏报计划来省略。未触发、跳过、取消、失败、缺少有效证据或仍未完成，均不构成完整验证成功；流水线汇总为 `passed` 不能覆盖这些事实。预期独立于候选且能区分方向的测试可提供目标证据，通过本身不证明这种区分力。语义歧义未解决时，依赖该选择的修改与发布保持 `stop`。

仅后续合并、部署等本次目标之外的动作未获授权，不影响本次修复成功判断。`queued` / `running` 是带观察时间的进度，不是最终结局；等待和后续观察沿用原权限、预算及实时观察边界。
