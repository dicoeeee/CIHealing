# 执行模式

写入式诊断实验、候选修改或验证前，读取下方工作空间规则及适用模式；关键缺口需要协作时，转到[交互与移交](collaboration.md#交互与移交)。无已授权且可用通道时，直接报告缺口与继续条件并结束，不等待、不承诺续接或自动创建通信任务。模式选择以[入口](../SKILL.md#选择模式)为准，本文件不重新选择模式或授予权限。

## 运行时上下文

| 上下文 | 含义 |
| --- | --- |
| `local_checkout` | 在本地仓库检出中进行交互式或自动化修复 |
| `inline_ci_job` | Job 结论固化前，由能捕获失败命令的包装器调用修复 |
| `terminal_repair` | Provider 已固化步骤或 Job 失败后才开始修复 |

运行时上下文不是验证模式，也不证明协作能力。`local_verify` 可在以上任一工作空间中执行；`terminal_repair` 的本地验证不能改写已固化的原 CI 结论。

## 基线与候选恢复

工作空间保护要求保留修改归属与恢复依据，不表示介入时的内容正确、稳定或不得作为修复对象。满足修复准入且处于授权范围内的内容，可以进行必要修改、整合或删除；仍须按下方规则保留原始内容，并在放弃候选时安全恢复，不能覆盖无关或并发修改。不得仅凭内容由失败变更新增或参与失败机制，就认定其应被删除，或免除恢复责任。

- 同一次 Healing Session 对每个参与仓库分别固定 `baseline_sha`，关联仓库身份和实际工作空间；单仓调用只有一项，多仓调用按[仓库与基线绑定](core-contracts.md#仓库与基线绑定)分别记录。每个基线用于对应仓库的 Git 来源追溯和远端候选 ref 创建，不一定等于介入时的工作空间内容，也不是撤销本轮修改时的默认恢复目标。
- 流水线 Job 已提供独占工作空间时，以宿主指定且后续提取脚本会读取的目录为修复和编译目录。不要自行切换到脚本无法读取的临时 checkout；确需另一个目录时，遵循宿主已声明的目录交接方式。
- 工作树脏本身不要求更换目录。先识别用户和流水线已有的修改、继承的候选及相关未跟踪文件；共享目录无法安全开展修复时，在开始修改前选择保留所需输入的隔离环境，或按关键缺口规则处理。
- 在首次修改相关位置前，保留其原始内容和文件原本是否存在的依据；这也适用于诊断实验、临时插桩和会改写文件的命令。由 Agent 跟踪自己的改动，不要求备份整个工作空间、生成完整 Patch 或提供专用快照/恢复脚本。
- 决定放弃一个候选时，Agent 自行撤销该候选引入的修改：恢复被改写或删除的原有内容，仅移除可确认由本轮新增且未被其他参与者改动的文件，保留用户和 Job 预先存在的内容。恢复依据是修复介入时的内容，而不是直接取 Git 版本覆盖。可以跨 Attempt 保留证据与假设，但不能叠加被放弃候选的代码修改。
- 恢复后读取相关文件并检查差异及文件存在性，确认被放弃候选无残留，再构建下一候选。原始依据缺失、出现并发修改，或无法区分命令副作用的归属时，暂停相关写操作，报告未恢复项并按[交互与移交](collaboration.md#交互与移交)处理；取得可核对的恢复依据前，不猜测性覆盖，也不对用户工作空间做整体 reset、checkout 或清理。
- 验证前为实际候选代码状态生成 fingerprint；纳入参与验证的已有修改和相关未跟踪文件，区分原有内容与本轮修复。这用于绑定被验证的状态，不要求导出 Patch 文件。

例如，Git 中配置为 `A`，Job 准备阶段改为 `B`，Agent 改为 `C` 后放弃候选，应恢复为 `B`，而不是 `A`。

构建副产物清理与放弃候选是两种操作。会在源码工作空间产生或改写文件的诊断、构建或验证，执行前读取[清理与校验](workspace-cleanup.md)；该指南统一定义编译前基准、清理闭环、撤销候选后的基准处置，以及成功交付和缺口移交的不同条件。

## `local_verify`

取得本地候选准入后，在已确认工作空间执行候选修改与验证计划，按已读准入指南的结果判据决定交付、继续候选或结束，沿用核心合同确定的调用身份和循环限额。

在 `inline_ci_job` 中，包装器须在结论固化前捕获失败命令并保留证据，且仅在满足本地验证合同时返回成功。若 Provider 已固化失败步骤或 Job，按 `terminal_repair` 保留该失败事实，不将工作空间验证成功描述为原始流水线已通过。

## CI Job 工作空间交付

在远端 Runner 的指定 Job 工作空间内修改、编译并交给后续脚本提取 Patch，属于 `local_verify`。本场景不执行 commit、push，不发布候选 ref，也不自动触发另一轮流水线；Agent 在最终报告中说明实际留下的代码及其验证范围。

后续脚本负责 Patch 提取、打包和归档；Skill 无需导出完整 Patch，也不以是否已导出作为验证成功前提。成功交付须满足[清理完成条件](workspace-cleanup.md#结束与协作)；未满足时仍报告缺口，不能将候选标为已清理、可安全提取。交付后保持待提取内容不变，不 reset、清理或继续改写。脚本需在工作空间销毁前接手，Skill 只能报告已观察事实，不能声称尚未观察到的提取或持久化已完成，也不能保证外层脚本会因本次清理失败而停止。

传入 `output_dir` 时按[变更文件清单](file-change-manifest.md)交付 `file_change.json`，供外部系统确定待提取文件。清单与工作空间一致，但不替代上述清理、归属与交接条件；无代码修改仍交付空数组。

## `remote_verify`

另行远端验证时读取 [远端执行指南](remote-verification.md)和 [Provider 合同](provider-contract.md)。本地工作空间规则仍适用；外部写入的权限与步骤不从 Job 运行位置推导。

## 结果报告

最终交付前读取[文字版结果报告](result-report.md)，按其固定结构、输出方式和交付检查完成报告；需要协作时沿用本文件开头的条件入口。
