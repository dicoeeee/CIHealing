# 执行模式

不同模式共享修复逻辑；模式只改变验证发生的位置、实时生命周期由谁负责，以及是否允许发布候选。

## 运行时上下文

| 上下文 | 含义 |
| --- | --- |
| `local_checkout` | 在本地仓库检出中进行交互式或自动化修复 |
| `inline_ci_job` | CI Job 结论固化前，由能够感知失败的包装器调用修复 |
| `terminal_repair` | Provider 已经固化步骤或 Job 失败后才开始修复 |

运行时上下文与验证模式有关但不相同。`local_verify` 指在 Agent 当前工作空间中编译和验证，也包括运行在远端 Runner 上的流水线 Job。本地检出可以选择触发另一轮流水线的 `remote_verify`；末端修复若要获得新的外层 CI 成功，需要新的远端运行。仅在当前工作空间修复并交给后续 Patch 提取脚本时，使用 `local_verify`，不改变原流水线结论。

## 基线与候选恢复

- 将 Healing Session 绑定到一个 `baseline_sha`，用于 Git 来源追溯和创建远端候选 ref；它不一定等于修复介入时的工作空间内容，也不是撤销本轮修改时的默认恢复目标。
- 流水线 Job 已提供独占工作空间时，以宿主指定且后续提取脚本会读取的目录为修复和编译目录。不要自行切换到脚本无法读取的临时 checkout；确需另一个目录时，遵循宿主已声明的目录交接方式。
- 工作树脏本身不要求更换目录。先识别用户和流水线已有的修改及相关未跟踪文件；共享目录无法安全开展修复时，在开始修改前选择保留所需输入的隔离环境，或停止。
- 在首次修改相关位置前，保留其原始内容和文件原本是否存在的依据；这也适用于诊断实验、临时插桩和会改写文件的命令。由 Agent 跟踪自己的改动，不要求备份整个工作空间、生成完整 Patch 或提供专用快照/恢复脚本。
- 决定放弃一个候选时，Agent 自行撤销该候选引入的修改：恢复被改写或删除的原有内容，仅移除可确认由本轮新增且未被其他参与者改动的文件，保留用户和 Job 预先存在的内容。恢复依据是修复介入时的内容，而不是直接取 Git 版本覆盖。可以跨 Attempt 保留证据与假设，但不能叠加被放弃候选的代码修改。
- 恢复后读取相关文件并检查差异及文件存在性，确认被放弃候选无残留，再构建下一候选。原始依据缺失、出现并发修改，或无法区分命令副作用的归属时，停止并返回 `inconclusive`，报告未恢复项；不要猜测性覆盖，也不要对用户工作空间做整体 reset、checkout 或清理。
- 验证前为实际候选代码状态生成 fingerprint；纳入参与验证的已有修改和相关未跟踪文件，区分原有内容与本轮修复。这用于绑定被验证的状态，不要求导出 Patch 文件。

例如，Git 中配置为 `A`，Job 准备阶段改为 `B`，Agent 改为 `C` 后放弃候选，应恢复为 `B`，而不是 `A`。验证成功的修改则保留在指定工作空间中，供后续脚本提取。

## `local_verify`

对于 `local_checkout`：

1. 捕获原始失败和基线。
2. 完成诊断并获得 `allow_local_candidate`。
3. 在隔离工作区或明确的工作范围内应用候选。
4. 运行 V0、V1 以及适用的 V2/V3 检查。
5. 返回 `local_verified`，或以新的 Attempt 继续，或带着相关结果停止。

对于 `inline_ci_job`：

- Job 包装器必须在不可逆地固化 Job 之前捕获失败命令。
- 将原始失败保留为证据，在宿主指定的 Job 工作空间修改代码，并运行编译及其他已声明的检查。
- 只有候选满足已配置的本地验证合同时，包装器才可以返回成功。
- 如果 Provider 已经固化失败步骤或 Job，将其视为 `terminal_repair`，保留原始失败结论。当前工作空间验证可按 `local_verify` 完成并交给后续脚本，但不能据此声称原始流水线已经通过。

流水线内修复完成后，将已验证的代码修改留在指定工作空间中，报告工作空间绝对路径、`baseline_sha`、修改文件和编译/验证结果，供后续脚本提取 Patch。提取、打包和归档由该脚本负责；Skill 无需生成完整 Patch 文件，也不以 Patch 是否已导出作为本次验证成功的前提。

由后续脚本接手提取时，验证成功后不要 reset、清理或继续修改待提取的修复内容，不要擅自 commit 改变脚本使用的差异基线。后续脚本应在工作空间销毁前接手；Skill 只能报告已修改、已验证的事实，不能声称脚本已完成提取或持久化。

## `remote_verify`

前置条件：

- Provider 或 SCM 适配器能够发布候选并识别其准确生成的 SHA；
- Provider 能够触发或解析与该 SHA 关联的流水线；
- 可以直接或通过外部 Harness 观察该运行直到终态；
- 验证计划已区分发布前本地预检与可在远端完成的检查，并将远端承担的 V1/V2 及适用的 V3 映射到具体命令或 Job/Check；
- 候选具有 `allow_remote_candidate`。

本地不具备原失败的工具链或运行环境时，可以将该检查安排在远端；远端模式不要求先达到 `local_verified`。发布前检查和最终成功条件以[诊断与修复的分层验证规则](diagnosis-and-repair.md#分层验证)为准。

工作空间已有修改不自动获得发布授权。远端候选仍以 `baseline_sha` 为 Git 起点，只纳入获准的修复；移到候选 ref 后若代码或相关输入发生变化，原工作空间的通过收据不能直接沿用，须重新执行受影响的发布前检查。

执行：

1. 核验 V0 和明确声明的发布前本地预检已有当前候选的通过收据，补跑缺失或已失效的检查；任一必需发布前检查失败或无法完成时不得发布。尚未执行、已安排在远端完成的本地检查保留 `not_run` 并记录原因。
2. 从固定 Git 基线为 Healing Session 和 Attempt 创建唯一的专用候选 ref。
3. 只 commit 连贯的候选差异，然后 push 该专用 ref。
4. 如果 push 已经触发目标流水线，则解析并观察该运行，不要重复 dispatch；否则调用 Provider 的显式触发能力。
5. 记录候选 SHA、Provider 运行身份和观察时间。
6. 逐项核对已声明的远端检查，取得远端承担的 V1/V2 及适用的 V3 的实际执行结果。检查未触发、跳过、取消或证据不完整时不得按通过处理；实际失败时，将新证据归一化，并判断是否有理由从基线生成另一个候选。
7. 只有当发布前检查、计划内全部必需验证和 V4 都有属于准确候选的通过证据时，才返回 `outer_ci_passed`。不得用流水线整体变绿替代缺失的逐项验证，也不得将本地 `not_run` 或 `incomplete` 改写为通过。

远端模式授权自动 commit、push 到专用候选命名空间、触发流水线和观察结果，但不授权：

- 直接写入默认分支或受保护分支；
- 覆盖已有用户分支或共享分支；
- merge、tag、发布、部署或生产动作；
- 弱化检查或修改分支保护；
- 自动删除或清理分支。

优先为每个 Attempt 使用唯一 ref。不要对已有用户或共享 ref 执行 force-push。任何 Provider 专用替代方案都必须保留基线隔离、候选身份、可审计性和幂等性。

## 末端转换

当失败结论已经固化，且任务还要求获得新的外层 CI 结论时：

```text
terminal_repair
  -> local diagnosis and candidate guard
  -> remote candidate publication
  -> new outer CI run
```

如果所需远端能力不可用，保留已生成的候选及实际取得的本地验证收据，并带着缺失能力返回 `inconclusive`。仅在满足本地模式全部验证条件时才能描述为本地已验证；不要将旧的失败运行重新解释为已自愈。

## 有界循环

- 默认最多进行五个完整候选 Attempt；遵守更小的仓库限制。
- 第一个有效成功出现时立即停止。
- 后续工作不再增加信息、策略拒绝动作、证据不足，或时间/计算预算耗尽时提前停止。
- 使用候选差异、依赖上下文、基线证据和观察到的验证结果，将新失败分类为 related、unrelated 或 uncertain。保留分类依据，不使用固定分数。
- V4 期间的基础设施或 Provider 失败，会使该观察对候选正确性而言不完整。将其路由到适当的恢复机制或返回 `inconclusive`；不要通过无限重试基础设施来消耗修复 Attempt。

## 结果报告

本地模式需要报告实际修复/验证的工作空间绝对路径、`baseline_sha`、候选 fingerprint、修改文件、实际运行的命令、结果和未覆盖的外层检查。流水线内由后续脚本提取 Patch 时，说明修复内容已留在该目录供脚本读取，不要求附带完整 Patch 文件。

远端模式还需要报告专用 ref、候选 SHA、触发方式、Provider 运行身份、最近观察时间、已观察到的终态结果，以及 Harness 是否需要继续调用。按验证计划区分本地预检与远端承担的检查，逐项列出结果和证据，并如实保留本地未执行或未完成的记录。
