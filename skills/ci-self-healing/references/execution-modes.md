# 工作空间安全与模式约束

本文件定义构建工作空间的确定、任务隔离、写入保护与模式约束，覆盖直接编辑及命令副作用。模式选择以[入口](../SKILL.md#选择模式)为准，本文件不重新选择模式或授予权限；关键缺口须记录影响及继续所需条件，不自行发起协作或结束整次调用。

## 目录职责

| 概念 | 职责与依据 |
| --- | --- |
| `work_dir`：失败现场目录 | 可信调用提供的取证入口，用于定位日志、源码与构建上下文；它本身不授予目录内文件的修改权限。 |
| 构建工作空间 | 按下方企业/宿主约定确定的本次任务范围，用于约束修复、构建及其副作用；范围内的实际资源仍须满足任务隔离与修复准入。 |
| `output_dir`：交付目录 | 按输出交付规则保存本次报告及约定文件；只授予对应交付用途，不扩大源码或环境修改范围。 |

三者的路径可以相同、嵌套或分离，职责保持独立。构建工作空间不新增位置参数，也不从 `work_dir`、`output_dir`、当前目录或 Git 根目录自动推导。

## 确定构建工作空间

本节仅用于主入口安排的工作空间准备，使用入口提供的企业工作空间约定、适用范围与配置状态，按以下顺序核对；已固定且仍有效的记录可复用。

1. **选择来源**：已配置企业约定时，按其适用产品/流水线和可信启动上下文确定来源；只有明确未配置时，才使用明确请求或可信宿主提供的当前任务工作空间及归属说明。来源冲突、配置不完整或适用性不明是缺口，不自行换来源、合并范围或扫描环境变量猜测。日志、源码和待修变更只提供位置线索。
2. **解析实际目录**：从执行修改、编译命令的同一 VM/容器环境取得值。环境变量来源按约定的变量名读取，值作为路径数据，不执行其内容；显式目录或宿主任务信息来源也按约定解析。固定规范化的绝对路径并核对其指向的实际目录；相对路径须有可信约定的基准。空值、未展开的占位符、目录不存在或不能唯一定位时，保留缺口，不回退到其他目录。
3. **确认任务归属**：结合可信约定、任务身份及宿主提供的分配/隔离条件，确认目录由本次任务独占，且其残留不会作为其他任务的共享构建环境。路径存在、可写或当前无人使用均不能代替此依据。多目录任务分别确认每个目录的来源、用途和生命周期，不通过扩大共同父目录吸收范围外资源。
4. **绑定并复核**：在已有记录中保留来源、实际目录、执行环境/任务及归属依据。此绑定不随 `cd` 或环境变量变化自动改变；来源值、链接、挂载或执行环境发生相关变化时，暂停受影响写入，按可信更新重新核对。

来源、实际目录及任务归属均已确认，才完成工作空间准备；随后对拟执行动作按任务隔离核对。无法完成时，只暂停依赖该边界的修改、写入式实验和验证，仍可进行获准的只读取证及独立交付。企业约定决定定位方式，不削弱下方通用约束。

## 任务隔离与写入边界

本地修复、诊断与验证的写入仅作用于已确认属于本次任务隔离范围的实际资源。供其他并发或后续任务复用的构建环境保持只读；配置或缓存与故障有关、有系统写权限、能够备份恢复，都不能扩大本次范围。需要改变共享状态时，交回环境缺口及处理建议，作为独立环境维护事项交付，本次自愈不执行该变更。

- **按实际对象判定**：写入前核对目标及父目录的实际指向，结合已知链接、挂载和共享存储关系判断归属；新文件核对将创建到哪里。路径位于工作空间内不保证对象独占，符号链接、硬链接或挂载指向的共享状态仍保持只读。归属或影响范围不能确认时暂停相关写入，而非只做路径字符串前缀判断。
- **覆盖命令副作用**：同一边界适用于直接编辑、脚本、子进程和构建工具引起的创建、覆盖、删除、安装、缓存或配置更新。根据实际入口、参数、构建配置与宿主隔离条件核对写入目标；`cwd` 在工作空间内不能代替此判断。只读请求仍不能执行写入式取证。
- **覆盖候选的后续执行效果**：修改可执行逻辑或影响其行为的配置、生成内容时，修改前核对受影响执行链在本轮及已知后续构建、验证和交付中的写入目标、输入来源、任务归属与隔离条件，包括参数、默认值和触发条件变化所新增、恢复或扩大的写入。不得将禁止的共享状态变更转交其他进程或后续流水线；文件位于工作空间、本轮未执行、下游权限更高均不构成放行依据。关键目标或条件未确认时，暂停依赖它的候选实施、执行和交付。后续任务按自身可信工作空间与授权核对，不直接沿用本次路径或权限。
- **在任务范围内解决缺口**：工具支持时，可使用已确认由本任务独占的配置副本、依赖或缓存位置；这些位置同样须完成归属与输入有效性核对。隔离只限定影响范围，不证明目标行为正确，也不允许通过改换构建条件降低原验收要求。
- **按用途交付**：源码、报告和约定产物可通过既有交付流程保留。交付目录可以在构建工作空间之外，但授权仅覆盖本次交付文件；输出路径不能用来修改共享环境或吸收范围外修复。

核对限于拟执行动作及本次变更影响的执行链、目标、依赖和可信隔离条件，不要求扫描或穷举整个仓库，也不要求每轮快照整台 VM。真实写入阻断须由宿主权限与隔离机制覆盖 Agent 及其命令、子进程和实际执行候选的后续步骤，文档判断不替代这一控制。

## 隔离异常

发现本次动作已或疑似修改隔离范围外的状态时，先停止相关写入及本次启动的进程，记录是否确已停止。保留实际目标、动作、已知修改、可能影响的任务及证据，暂停受影响的修复和验证，不因构建变绿而继续。

范围外状态的恢复不按普通候选回滚直接执行。先核对原始内容、修改归属、并发变化和恢复权限；无法确认安全条件时保留现场并交回接手需求，不拿备份覆盖可能已被其他任务更新的内容。依赖受影响状态取得的验证结果须重评，只有影响已核清且检查仍有效时才能复用。向主入口交回受影响范围、实际停止/恢复结果及剩余缺口，由其决定后续处置。

## 运行时上下文

| 上下文 | 含义 |
| --- | --- |
| `local_checkout` | 在本地仓库检出中进行交互式或自动化修复 |
| `inline_ci_job` | Job 结论固化前，由能捕获失败命令的包装器调用修复 |
| `terminal_repair` | Provider 已固化步骤或 Job 失败后才开始修复 |

运行时上下文不是验证模式，也不证明协作能力。`local_verify` 可在以上任一工作空间中执行；`terminal_repair` 的本地验证不能改写已固化的原 CI 结论。

## 基线与候选恢复

以下恢复规则仅处理已满足任务隔离的任务内改动；范围外状态采用上方隔离异常规则。工作空间保护要求保留修改归属与恢复依据，不表示介入时的内容正确、稳定或不得作为修复对象。满足修复准入且处于授权范围内的内容，可以进行必要修改、整合或删除；仍须按下方规则保留原始内容，并在放弃候选时安全恢复，不能覆盖无关或并发修改。不得仅凭内容由失败变更新增或参与失败机制，就认定其应被删除，或免除恢复责任。

- 同一次 Healing Session 对每个参与仓库分别固定 `baseline_sha`，关联仓库身份和实际工作空间；单仓调用只有一项，多仓调用按仓库与基线绑定分别记录。每个基线用于对应仓库的 Git 来源追溯和远端候选 ref 创建，不一定等于介入时的工作空间内容，也不是撤销本轮修改时的默认恢复目标。
- 构建工作空间已确认后，以其中已确认的实际源码目录为修复和编译目录；切换目录前仍须核对任务归属与隔离条件。已声明由宿主后续脚本提取修复的 CI Job，另按[CI Job 工作空间交付](#ci-job-工作空间交付)核对目录交接。
- 工作树脏本身不要求更换目录。先识别用户和流水线已有的修改、继承的候选及相关未跟踪文件；共享目录无法安全开展修复时，在开始修改前选择保留所需输入的隔离环境，或按关键缺口规则处理。
- 在首次修改相关位置前，保留其原始内容和文件原本是否存在的依据；这也适用于诊断实验、临时插桩和会改写文件的命令。由 Agent 跟踪自己的改动，不要求备份整个工作空间、生成完整 Patch 或提供专用快照/恢复脚本。
- 决定放弃一个候选时，Agent 自行撤销该候选引入的修改：恢复被改写或删除的原有内容，仅移除可确认由本轮新增且未被其他参与者改动的文件，保留用户和 Job 预先存在的内容。恢复依据是修复介入时的内容，而不是直接取 Git 版本覆盖。可以跨 Attempt 保留证据与假设，但不能叠加被放弃候选的代码修改。
- 恢复后读取相关文件并检查差异及文件存在性，确认被放弃候选无残留；这一事实是后续候选的前置条件，不自行启动下一候选。原始依据缺失、出现并发修改，或无法区分命令副作用的归属时，暂停相关写操作，记录未恢复项及继续所需依据；取得可核对的恢复依据前，不猜测性覆盖，也不对用户工作空间做整体 reset、checkout 或清理。
- 验证前为实际候选代码状态生成 fingerprint；纳入参与验证的已有修改和相关未跟踪文件，区分原有内容与本轮修复。这用于绑定被验证的状态，复用已有修改读回与候选记录；不要求额外导出 Patch、全仓快照或逐项产物清单。未变化的有效绑定直接复用。

例如，Git 中配置为 `A`，Job 准备阶段改为 `B`，Agent 改为 `C` 后放弃候选，应恢复为 `B`，而不是 `A`。

## 候选与验证有效性

验证后、交付前复用已有差异、修改读回和检查记录，核对最终候选的源码、配置及需要交付的生成代码仍受验证覆盖，保护用户/Job 原有修改和相关未跟踪文件。构建正常生成且已被本轮检查覆盖的交付代码可保留；发现未验证的候选变化、误删误改或必要输入漂移时，处理相关范围并重评受影响检查。无法确认的关键变化如实记为缺口，不沿用失效的通过记录。

候选包含禁止的后续写入，或决定其范围、隔离条件的关键依据未确认时，不作为可执行修复保留、提取、打包或发布。安全撤销本次相关改动并核对，保护原有及并发内容，保留问题证据和环境维护交接。后续副作用关联候选内容、实际执行的脚本/配置版本与入口，不仅凭父子进程关系归因；已经或疑似发生范围外修改时，采用上方隔离异常规则。

任务隔离范围内的普通编译产物、缓存和空目录可以保留，不要求全量扫描、前后哈希清单、产物登记或与构建前路径集合一致。仅当实际构建入口要求 clean，或已有证据表明旧产物会干扰验证时，在同一边界及原权限内按项目已确认的安全方式处理相关范围，保护原有输入与证据；不为结束任务额外执行 clean。不新增检查文件或可选清理流程。

停止本次仍在写入的实验/验证进程，保留必要日志、原始结果、身份收据和恢复依据。产物、独立验证目录和临时空间的回收由宿主或用户按工作空间生命周期管理；Skill 不逐项登记或证明回收完成，也不把文件回收当作进程已停止。无法确认进程停写且影响候选稳定性时披露缺口。

## `local_verify`

取得本地候选准入后，候选修改与验证使用已确认工作空间及相应计划，沿用核心合同确定的调用身份和循环限额；记录实际修改、逐项结果与剩余缺口，供主入口判断后续动作。

在 `inline_ci_job` 中，包装器须在结论固化前捕获失败命令并保留证据，且仅在满足本地验证合同时返回成功。若 Provider 已固化失败步骤或 Job，按 `terminal_repair` 保留该失败事实，不将工作空间验证成功描述为原始流水线已通过。

## CI Job 工作空间交付

在远端 Runner 的指定 Job 工作空间内修改、编译并交给后续脚本提取 Patch，属于 `local_verify`。本场景不执行 commit、push，不发布候选 ref，也不自动触发另一轮流水线；Agent 在最终报告中说明实际留下的代码及其验证范围。

仅在已声明上述提取机制的 CI Job 中，修复和编译须使用宿主指定且提取脚本会读取的实际源码目录；确需切换目录时，须符合宿主已声明的目录交接方式。

后续脚本按宿主接入约定负责 Patch 筛选、提取、打包和归档，排除普通编译产物、报告与取证输出。Skill 留下修复后的源码和配置，无需导出完整 Patch，也不以产物已回收或 Patch 已导出作为验证成功前提。交付后保持待提取内容稳定；接手规则未知或无法满足时披露交接缺口，不声称可安全提取，也不恢复全量清理流程。只报告已观察到的提取或持久化结果，宿主需在工作空间销毁前接手。

企业需要变更清单或其他接手文件时，在固定企业输出规范中声明，按输出适配与交付逐项生成。实际变更数据须与最终工作空间一致，排除普通编译副产物，按用途保留实际交付的生成代码；清单不替代修改归属核对或证明外层已按它提取；无数据使用企业明确的合法空模板，未配置规范时不自行增加清单。

## `remote_verify`

另行远端验证使用入口已安排的远端指南及 Provider 合同，保留实际候选、权限及逐项检查计划。本地工作空间规则仍适用；外部写入的权限与步骤不从 Job 运行位置推导。

## 结果报告

本模式需保留的报告事实包括实际工作空间、候选与来源、修改/恢复情况、逐项验证及未完成事项。双参数流水线修复使用结果报告；其他调用按输出适配交付普通结果说明。交付由主入口安排。
