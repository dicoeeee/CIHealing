# 验证副产物清理与校验

修复调用在受控源码工作空间中执行会产生或改写文件的诊断、构建或验证前读取本指南；只读诊断不因此进入写入流程。适用于本地验证和远端发布前的本地预检，不代替外层 CI 的检查。

Agent 判断差异归属并执行安全清理、恢复或候选重评；[workspace_check.py](../scripts/workspace_check.py)只采集文件状态、比较并给出事实结论，不执行构建、源码删除/恢复、Git 操作或 Patch 提取。对差异的解释用于选择下一步，不授予豁免校验的权力。校验清单不是备份，恢复依据仍按[基线与候选恢复](execution-modes.md#基线与候选恢复)保留；脚本自身状态文件的交付见[状态文件与异常](#状态文件与异常)。

## 执行前条件

### 基准与差异的含义

- **范围**：确认实际源码根及多仓范围，覆盖未跟踪、隐藏及被 Git 忽略的文件。不能只提交“预计会有产物”的目录，也不能因发现差异而缩小范围。脚本不知道外层提取器会收集什么；Agent 必须披露范围外及未知的收集边界。
- **写入与恢复**：确认诊断、构建和清理期间无并发写入，并具备相关位置的恢复依据；校验前须停止相关写入。脚本的漂移检查不阻止其他进程修改文件。
- **包含当前候选的构建副作用基准**：修改前保留的恢复依据用于撤销候选；本指南的编译前基准须在候选应用完成后采集，用于检查本组构建副作用，不用于比较修复前后代码。两者不能互相替代，也不是 Git HEAD。顺序是保留恢复依据、实施获准候选、采集基准、执行检查、清理、校验。首次诊断实验尚无候选时，对实验前工作空间采集并使用实验绑定，不冒充候选准入。
- **历史产物**：采集前已存在的产物会被记录并保留，不会被自动判为垃圾。确需清理时，先凭项目/宿主约定确认可丢弃范围及对验证条件的影响，再由 Agent 处理；`match` 不能证明整个目录没有历史冗余。

### 使用脚本

使用 Python 3.9+ 标准库及 POSIX 描述符相对、不跟随链接的文件访问能力；首版面向 Linux/macOS 文件系统，其他平台返回能力缺口。先查看实际帮助，不新增 Skill 主入口参数：

脚本为 `scripts/workspace_check.py`，通过宿主指定的脚本工具执行。下面是两次调用的有序参数，不包含解释器或 shell 启动语法：

```json
["capture", "--help"]
["check", "--help"]
```

在有权限的范围内准备独立状态目录，位于所有检查根及已知 Patch 收集范围之外。有效且位于范围外的 `output_dir` 可承载清单，否则选择获准的独立临时目录；不能把清单塞进源码再要求检查忽略它。清单与 JSON 结果含路径及哈希，不含源文件正文，也不应进入 Patch。报告仍按原[输出约定](output-delivery.md#输出方式)交付，不擅自改写调用参数；若报告写入检查范围会使最终状态改变，先解决布局与交付约定的冲突，不把写入前的 `match` 当作最终收据。

下方示例路径和标识均须替换为实际值；`--root` 可重复传入不重叠的源码根，`--candidate-id` 引用本次实际工作空间/候选记录。基准清单必须不存在，父目录必须已存在。范围、恢复依据、执行能力或布局仍有关键缺口时，先处理缺口，不开始依赖它的命令。

## 执行闭环

### 采集基准

执行会产生副产物的命令前，确认当前候选已应用且此后未变，再运行 `capture`；先采集后改候选不满足该前提：

`scripts/workspace_check.py` 的有序参数：

```json
["capture", "--root", "/ci/work/sourcecode/repo-a",
 "--manifest", "/ci/healing-output/check-001-before.json",
 "--invocation-id", "invocation-001", "--candidate-id", "candidate-001"]
```

取得成功采集收据后，保留 `captured`、清单路径、`manifest_sha256` 和调用/候选绑定。该摘要按脚本的规范化 JSON 内容计算，不是文件原始字节的 SHA-256；直接复用返回值，不用 `sha256sum` / `shasum` 的文件摘要替代。采集不完整或脚本不可用时，先处理缺口，不绕过它执行会产生副产物的命令。

清单不可覆盖；不得编辑清单后重算摘要、增加忽略项，或在污染状态下重新采集来放行。确有新候选时使用新的路径和绑定，并保留变更与验证依据。依赖同一批产物的一组验证可以共享一个基准，组内不得穿插候选修改。

### 执行与清理

执行原诊断实验或验证计划并保留实际结果；无论通过、失败或中止，确认相关写入已停止，再由 Agent 核对副产物、修改归属及交付需要，执行安全删除或恢复。不能边编译边清理，不能把新增文件或目录名自动等同于垃圾；不对整个工作空间做 reset、checkout 或无差别 clean。

#### 优先选择安全的原生 clean

所有依赖编译产物的检查完成、必要证据保存并读回后，优先考虑构建工具或项目提供的 `clean`。执行前核对实际工具/插件版本、配置、模块、输出路径、附加删除规则和链接处理，确认删除范围均为本次可丢弃内容，并沿用构建时的隔离、网络与时限约束。命令名叫 `clean` 不证明它安全；它也是会写入的项目命令。

清理按**实际构建系统**选择，适用于各种语言；不根据语言名、文件扩展名或仅存在某个构建文件猜命令。复用本次验证使用的项目入口、工具链、模块、配置及输出位置；混合语言/多模块现场分别核对。下表是选择示例，不是支持语言或工具的封闭名单，也不表示宿主已实现对应适配器：

| 已确认的构建入口 | 原生清理候选与边界 |
| --- | --- |
| Maven、Gradle / Wrapper | 使用已确认的 clean goal/task 及同一模块范围，检查插件/任务的实际删除规则；不假定整个 `target` 或 `build` 都属于本次产物 |
| CMake、Make、Ninja | 针对本次构建目录选择 `cmake --build <dir> --target clean`、已定义的 `make clean` 或生成器清理入口；Make 的 clean 规则需读回核对，CMake 配置缓存等残留仍单独回收 |
| Cargo | 使用匹配本次工作区、profile/target 和 `target-dir` 的 clean；不能清掉其他调用共用的目标目录 |
| Go | 按实际包和输出位置确定 clean 与产物回收范围；不默认加入 `-cache`、`-modcache`、`-testcache` 等共享缓存清理动作 |
| .NET / MSBuild | 对同一项目、配置、framework/runtime 的构建输出选择 clean；核对自定义 targets 的副作用 |
| JavaScript / TypeScript | 仅在项目确有对应脚本且内容、前后置钩子已核对时使用 `npm/pnpm/yarn run clean` 等入口；不把包管理器缓存清空当作编译清理 |
| Python 或其他项目任务 | 使用项目明确提供并已核对的清理任务；没有统一或可靠入口时直接按本次产物登记回收，不临时编造 clean 命令 |

项目清理任务可能是任意代码，仍在原有隔离与权限范围内执行。执行器缺少某个工具或插件时不切换成另一语言的清理器、不安装依赖；缺少原生 clean 本身不阻止安全的产物回收。保留所选命令的依据、参数与实际结果，不能把一类工具的测试通过扩展为所有语言均已验证。

- **原地源码工作空间**：输出目录可能包含原有 Job 文件或历史产物。默认整目录 clean 会删除这些文件时不执行，继续按基准精确处理。不能只保留文件名或摘要后删掉原内容，也不为匹配清理结果重采污染基准。
- **本次独占的验证副本**：创建者确认归属、保存可恢复的实际输入、命令/配置、日志和结果后，可先运行安全的原生 clean，再回收登记的副本。整个副本已可丢弃时也可直接回收，不强制重复执行 clean。
- **命令不可用或失败**：记录缺少插件、超时、退出码或其他实际原因；在同一授权范围内对登记产物执行安全回收。不自动联网下载、修改全局缓存、扩大删除范围或忽略原检查失败。
- **完成判据**：clean 的退出码只记录命令结果。它可能被配置为跳过、仅清理部分输出或产生新的临时文件，仍须执行源码一致性校验及下方范围外产物复核。

工具语义参考：[CMake 构建目标](https://cmake.org/cmake/help/latest/guide/user-interaction/index.html)、[Cargo clean](https://doc.rust-lang.org/cargo/commands/cargo-clean.html)、[Go clean](https://go.dev/cmd/go/#hdr-Remove_object_files_and_cached_files)、[npm scripts](https://docs.npmjs.com/cli/using-npm/scripts/)。实际使用以项目选定版本和配置为准。

#### 独立验证目录与本次临时产物

创建独立验证副本、编译输出、专用临时目录或私有缓存副本时，先登记实际路径、创建者、本次调用/阶段、原有状态及保留需要。优先使用本次独占的新目录；不能按目录名、后缀或修改时间把既存目录接管为可删除内容。共享缓存和原有文件保持原状。

谁创建谁负责收尾：Agent 处理其获准控制的目录；宿主创建的验证副本和运行期临时目录由宿主回收，Agent 只引用实际收据，不扩大权限操作宿主路径。范围外能力或归属未确认时披露缺口，不把源码 `match` 扩展为全调用清理完成。

收尾顺序为：确认相关写入停止 → 保存并读回必要证据 → 回收本次可丢弃产物 → 复查登记范围残留、原有文件和证据。日志、报告、原始轨迹、身份收据、恢复依据和不可重建的必要输入不当作临时垃圾；摘要不是备份。缺少必要证据时保留相关目录并报告未完成。删除不跟随链接越界，不跨挂载递归，不删除被其他参与者替换的目录。

通过、失败、超时、中断及部分初始化均须尝试有界收尾；无法确认进程已停或安全删除时保留现场。宿主被强杀不能承诺即时清理，保留登记与已完成证据供后续核对，不自动重跑模型或修复。文件回收与进程退出分别记录；后续清理生成新记录，不覆盖历史试次与原始结果。

脚本比较最终文件状态，不追踪构建中的每次写入，也不证明产物的语义或归属。构建改写源码、生成代码需要交付等情况仍须核对验证对象；恢复一致不自动消除候选输入漂移。仅移除不参与交付的输出不要求为清理再编译；若改变了必要输入，则重评受影响验证。

### 校验与处理

使用原清单、采集返回的原摘要及完整根目录集合运行 `check`，核对本次[返回结果与绑定](#返回结果与绑定)：

`scripts/workspace_check.py` 的有序参数：

```json
["check", "--root", "/ci/work/sourcecode/repo-a",
 "--manifest", "/ci/healing-output/check-001-before.json",
 "--manifest-sha256", "capture返回的64位摘要",
 "--invocation-id", "invocation-001", "--candidate-id", "candidate-001",
 "--output", "/ci/healing-output/check-001-result-01.json"]
```

根据下表继续；每次调整后重新检查，不能把旧收据当成当前事实。“正常编译输出”“被 Git 忽略”“来源已明确”都不使 `mismatch` 成为通过；空目录也属于路径差异，`git status` 或只列普通文件的检查不能替代脚本。候选已被否决或决定放弃时，先按[候选撤销与基准](workspace-recovery.md#候选撤销与基准)处理，不按原候选盲目恢复文件。

| 脚本事实 | Agent 的处理 |
| --- | --- |
| `match` | 声明范围内已与编译前状态一致；再核对清理是否改变必要输入、修复依据与验证收据是否有效，不直接等同于修复成功 |
| `mismatch`：残留副产物 | 查明来源后安全清理，再校验；不能因其属于预期输出而保留并宣称通过，无法安全清理时报告缺口 |
| `mismatch`：差异看起来正是拟保留的候选 | 先核对是否在候选应用前误采了基准、或组内修改了候选；属实时按[基准缺失或时序错误的恢复](workspace-recovery.md#基准缺失或时序错误的恢复)处理。不能以“都是预期源码修改”豁免，也不为匹配错误基准撤销仍有效的候选 |
| `mismatch`：原有或仍有效的候选文件缺失/被改写 | 根据可靠的原始内容恢复误删误改，再校验；无法确认归属或恢复依据时暂停相关写入 |
| `mismatch`：差异确实应成为新的修复 | 重新评估并记录候选准入，保留旧校验事实；取得新的候选基准并重做受影响验证，不仅为了消除差异而重新采集 |
| `incomplete`、无结果或结果绑定不符 | 解决读取、范围、预算或漂移问题后重查；仍无法完成时按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)协作或结束，不能宣称已清理或校验通过 |

需要恢复基准或撤销候选时，**在相关恢复、重新采集或撤销前**读取[清理基准恢复与候选撤销](workspace-recovery.md)。正常清理不加载该分支；历史违规与原始比较事实仍保留。

## 结束与协作

- **成功交付候选**：适用本指南时，须有绑定当前候选与完整根集合的有效采集收据和最新 `match`，同时核对本次登记的独立目录及临时产物已回收或有明确的必要保留依据，确认清理未使必要验证失效，再按[结果判定](repair-and-verification.md#结果判定)判断成功。发布或交给 Patch 脚本前核对状态仍一致，发生相关变化时重查；之后保持待交付内容不变。
- **缺口报告或协作**：`mismatch`、`incomplete`、脚本不可用或恢复不安全不阻止输出报告、提问或移交。暂停不安全的写入，按[交互与移交](execution-modes.md#交互与移交)说明当前文件状态、残留、恢复依据和继续条件；不能声称清理完成或候选可安全提取。报告写入仍遵循[输出约定](output-delivery.md#输出方式)。
- **结束结果**：因清理/校验缺口无法完成修复时返回 `inconclusive`；另有已确认的禁修等终止原因时按通用结果判定，同时披露清理缺口。保留编译通过等实际观察，不将其升级为完整成功。

清理循环共用[调用预算](core-contracts.md#调用身份与限额)。恢复和校验本身不新增修复 Attempt；形成新完整候选并进入验证时按原规则计数。没有进展、预算耗尽或无法安全清理时结束或协作，不反复盲删。

文件一致性、修复是否成功和报告是否交付分别判断。把校验范围、基准引用、实际清理、最新结果与残留问题汇入[结果报告](result-report.md)，不另设人工审批流程或 Patch 提取协议。

## 脚本结果与异常

### 返回结果与绑定

运行期结果输出到 stdout JSON，参数错误可能只有 stderr；同时核对退出码和下列观察，不只看文件是否存在：

| 操作与退出码 | 含义 |
| --- | --- |
| `capture`：0 | 清单已完整采集、写入并读回；不是编译或清理成功 |
| `check`：0 | `match`，检查范围与原基准一致 |
| `check`：1 | `mismatch`，存在差异，文件未被脚本更改 |
| 两者：2 | `incomplete` 或参数错误；参数错误可能只有 stderr，不得当作通过 |

JSON 包含实际根目录、调用/候选绑定、观察时间、固定排除范围及缺口；`compared` / `not_compared` 明确比较维度和未覆盖内容。差异按 `added`、`missing`、`changed` 给出前后类型、哈希和属性，不提供删除建议。`counts` 为完整计数，`differences_truncated` 表示详情被限额截断；仍是 `mismatch`，可增加详情限额重查，不把未展示项视为不存在。

`gaps` 保留原错误码及原因，并补充 `phase`、可确定的 `path` 和适用的 `errno`。例如 `scan` 表示源码观察失败，`manifest_read` / `manifest_validate` 表示基准读取/核对失败，`manifest_write` / `report_write` 表示状态文件交付失败。没有系统错误码或无法定位时相应字段可为空；读取失败不等于文件缺失，也不构成 `mismatch`。据实际阶段处理问题，不为修复报告写入错误而改动源码。

### 状态文件与异常

- `--output` 可省略；提供时只能创建范围外的新文件。比较完成得到 `match` 或 `mismatch` 后才发布校验 JSON 报告；扫描、基准或范围检查失败时，stdout 返回 `incomplete`，不保证生成报告文件。重复校验使用新结果文件名或只用 stdout，不能覆盖旧证据，原清单不变。
- `capture` 写入并读回清单后才返回 `captured` 与摘要；没有成功采集收据的清单不能作为已确认基准。根据实际失败阶段处理问题，已有文件和检查观察分别保留。

状态文件发布或收尾出现异常时，先读取[状态文件异常](workspace-recovery.md#状态文件异常)，分别核对发布结果、stdout/stderr 与最终绑定；文件存在本身不证明成功。

## 支持范围与局限

- 比较普通文件内容、文件/目录权限位、路径集合及符号链接目标；不跟随链接读取目标内容，不比较所有者、ACL、扩展属性、时间戳或硬链接拓扑。范围外链接目标及其他构建副作用由 Agent 单独核对，不能扩展 `match` 的含义。
- 仅固定排除每个根直属的 `.git` 元数据，不排除 `.gitignore` 或产物目录；不提供任意忽略参数。嵌套仓库、跨设备挂载及特殊文件返回 `incomplete`，需确认真实范围或补充能力，不能静默跳过。Git HEAD/index 的有效性仍按原合同核对。
- 采集/检查均进行两次流式内容读取，并核对观察期间的身份与时间属性，发现漂移即不完整；这不是原子文件系统快照，也不阻止其他进程写入。检查前停止相关写入并排除并发参与者，检查后仍可能漂移。
- 条目、读取字节及差异展示限额以 `--help` 为准；前两项超限会返回 `incomplete`，不会保存部分基准或报 `match`。目前单个目录仍先完整枚举、排序，再处理条目预算；该预算不是枚举内存或执行时间上界。读取成本与范围内全部文件大小相关，不因为大仓而自动省略被忽略文件。
- 清单摘要可发现误改和错用，但不是防篡改权限隔离。Markdown 访问检查支持简单的单行 `ai_access: true/false` 声明，识别引号外的注释和其他简单字段的完整单行标量；普通描述或行尾注释提及 `ai_access` 不成为访问声明。明确 false、别名/流式映射等无法确定的潜在声明仍阻止完整采集；不承诺完整 YAML、多行语法解释。获准时哈希覆盖整个文件，被拒绝时不继续正文哈希。其他访问规则仍由调用方遵守，不借哈希读取绕过限制。
- 脚本不保证 Agent 必定调用它，也不能约束外层提取器、处理已被强杀的进程或自动恢复文件。原始内容依据不足时报告缺口，不把哈希清单当备份。
