# 验证副产物清理与校验

修复调用在受控源码空间执行写入式诊断、构建或验证前读取；适用于本地验证及远端发布前预检，不替代外层 CI，也不使只读任务进入写入流程。

Agent 判断归属并安全清理、恢复或重评候选。[workspace_check.py](../scripts/workspace_check.py)只采集/比较状态，不构建、删除/恢复源码、操作 Git 或提取 Patch；差异解释不豁免校验。清单不是备份，按[基线与候选恢复](execution-modes.md#基线与候选恢复)另留原始依据，状态文件交付见[状态文件与异常](#状态文件与异常)。

## 执行前条件

### 基准与差异的含义

- **范围**：确认完整实际源码根及多仓范围，含未跟踪、隐藏、Git 忽略项；不只检查预计产物目录，也不因差异缩小范围。外层提取器的范围外/未知收集边界由 Agent 披露，脚本不能推断。
- **写入与恢复**：确认诊断、构建、清理期间无并发写入且有相关位置恢复依据，校验前停止相关写入；漂移检查不能阻止其他进程。
- **包含当前候选的构建副作用基准**：修改前留恢复依据用于撤销；`capture` 在完整候选应用后、检查组开始前采集，用于识别构建副作用，两者均不能互代或取 Git HEAD。顺序：恢复依据 → 获准完整候选 → capture → 检查 → 停止写入 → 清理 → check。首次实验无候选时采集实验前状态并用实验绑定，不冒充候选准入。
- **历史产物**：基准内原有产物保留；需删除时先据项目/宿主约定确认可丢弃范围及验证影响，`match` 不证明无历史冗余。

### 使用脚本

使用 Python 3.9+ 标准库及 POSIX 描述符相对、不跟随链接的文件访问能力；首版面向 Linux/macOS 文件系统，其他平台返回能力缺口。先查看实际帮助，不新增 Skill 主入口参数：

脚本为 `scripts/workspace_check.py`，通过宿主指定的脚本工具执行。下面是两次调用的有序参数，不包含解释器或 shell 启动语法：

```json
["capture", "--help"]
["check", "--help"]
```

在获准范围准备独立状态目录，位于所有根及已知 Patch 收集范围外；可用有效的范围外 `output_dir`，否则选获准独立临时目录，不改调用参数。状态文件含路径/哈希而非源码正文，不进 Patch，不放源码内要求忽略。与可丢弃输出分开登记，按[清单与结果保留](#清单与结果保留)保留；临时或范围外目录不意味着可删除。

报告按[输出约定](output-delivery.md#输出方式)交付；写报告会改变检查范围时先解决布局冲突，不沿用写前 `match`。示例替换实际路径/标识，`--root` 可重复指定不重叠根，`--candidate-id` 绑定实际记录；清单必须是新文件且父目录已存在。范围、恢复依据、能力或布局有关键缺口时，不开始依赖它的命令。

## 执行闭环

### 采集基准

执行会产生副产物的命令前，确认当前候选已应用且此后未变，再运行 `capture`；先采集后改候选不满足该前提。发现过早采集或检查组内候选变化时，先保留原清单，在重新采集前读取[基准缺失或时序错误的恢复](workspace-recovery.md#基准缺失或时序错误的恢复)，不能把旧清单当垃圾删除：

`scripts/workspace_check.py` 的有序参数：

```json
["capture", "--root", "/ci/work/sourcecode/repo-a",
 "--manifest", "/ci/healing-output/check-001-before.json",
 "--invocation-id", "invocation-001", "--candidate-id", "candidate-001"]
```

取得成功采集收据后，保留 `captured`、清单路径、`manifest_sha256` 和调用/候选绑定。该摘要按脚本的规范化 JSON 内容计算，不是文件原始字节的 SHA-256；直接复用返回值，不用 `sha256sum` / `shasum` 的文件摘要替代。采集不完整或脚本不可用时，先处理缺口，不绕过它执行会产生副产物的命令。

清单不可覆盖；不得编辑清单后重算摘要、增加忽略项，或在污染状态下重新采集来放行。确有新候选时使用新的路径和绑定，并保留变更与验证依据。依赖同一批产物的一组验证可以共享一个基准，组内不得穿插候选修改。

#### 清单与结果保留

- **原路径保留全部已发布证据**：执行、后续校验/评审及交接期间，保留所有 capture 清单、check 结果原文件和原始收据。误采、时序错误、被替代、候选撤销或最终 `match` 均不授权删除、覆盖、移动或重建；路径/摘要/摘录不能替代按旧回执可复核的原文件。
- **只标失效，不改原件**：在诊断/Attempt/报告中注明失效原因与后继基准，当前检查使用适用新绑定；保留旧文件不等于沿用旧基准，也不增加 Attempt。
- **不纳入副产物回收**：目录名含 `tmp`、Agent 创建或不进 Patch 均非删除依据。后续归档/保留期遵循宿主与交付约定；[状态文件异常](workspace-recovery.md#状态文件异常)只允许脚本回收自己创建且身份匹配的内部发布临时文件，不授权 Agent 删除正式证据。

旧清单丢失/改写须保留缺口；新 capture 或 `match` 不能补造旧绑定，按[结束与协作](#结束与协作)处理，不声称历史证据完整。

### 执行与清理

执行实验/验证计划并保留真实结果；无论通过、失败或中止，都先确认写入停止、保存并读回必要证据，再核对归属与交付需要，安全处理已确认可丢弃产物，排除上述审计文件。不边编译边清理，不把新增项自动当垃圾，不对全工作空间 reset、checkout 或无差别 clean。

**一次核对完整产物集合后再 check**：依据采集前状态、实际输出和本轮登记，清理本轮可丢弃文件，再由深到浅移除本轮新增且已空的目录（含 `generated-sources/annotations` 等嵌套目录）。保留原有空目录、Job 文件和必要输入；删除目录前核对归属、仍为空且未被其他参与者替换，不按名称整删 `target`/`build`。可将已确认安全的清理动作按顺序放在同一工具调用，完成后再运行原生 `check`；不得并行构建、清理与 check。发现残留仍按下方差异分支处理，不跳过校验。

#### 优先选择安全的原生 clean

所有依赖产物的检查完成、必要证据保存并读回后，优先选实际构建系统的安全 `clean`，不按语言、扩展名或构建文件猜命令。复用验证入口、工具链、模块、配置与输出位置；执行前核对工具/插件版本、删除规则、链接及附加副作用，混合语言/多模块分别核对，删除范围须全为可丢弃项。项目任务可能执行任意代码，沿用构建的隔离、网络、权限和时限约束，名字叫 clean 不保证安全。

以下仅为选择示例，不是支持清单、宿主适配器或跨语言验证证明：

| 已确认的构建入口 | 原生清理候选与边界 |
| --- | --- |
| Maven、Gradle / Wrapper | 同模块的 clean goal/task；核对插件/任务删除规则，不假定整个 `target`/`build` 可丢弃 |
| CMake、Make、Ninja | 本次目录的 `cmake --build <dir> --target clean`、已定义 `make clean` 或生成器入口；读回 Make 规则，另收 CMake 缓存等残留 |
| Cargo | 匹配本次工作区、profile/target、`target-dir` 的 clean，保留其他调用共用目录 |
| Go | 按实际包/输出选择，不默认清 `-cache`、`-modcache`、`-testcache` 共享缓存 |
| .NET / MSBuild | 同项目、配置、framework/runtime 的 clean，核对自定义 targets |
| JavaScript / TypeScript | 已存在且核对内容/前后钩子的 `npm/pnpm/yarn run clean` 等脚本，不清包管理器缓存 |
| Python 或其他项目任务 | 已明确提供并核对的任务；无可靠入口则按本轮登记回收，不编造命令 |

- **原地工作空间**：若整目录 clean 会删原 Job/历史内容则不用，按基准精确处理；文件名/摘要不能替代原内容，不重采污染基准来匹配。
- **独占验证副本**：确认归属、保存可恢复输入、命令/配置、日志和结果后，可安全 clean 再回收；副本已整体可丢弃时可直接回收，不强制再 clean。
- **缺工具/插件或命令失败**：记录原因、参数及结果，在原授权内回收登记产物；不换其他语言清理器，不自动安装/联网下载、改全局缓存、扩大删除或忽略验证失败。无原生 clean 不阻止安全回收。
- **完成判据**：退出码只证明命令结果；跳过、部分清理或新增临时文件仍可能发生，须做源码校验及下方范围外复核。

工具语义参考：[CMake 构建目标](https://cmake.org/cmake/help/latest/guide/user-interaction/index.html)、[Cargo clean](https://doc.rust-lang.org/cargo/commands/cargo-clean.html)、[Go clean](https://go.dev/cmd/go/#hdr-Remove_object_files_and_cached_files)、[npm scripts](https://docs.npmjs.com/cli/using-npm/scripts/)。实际使用以项目选定版本和配置为准。

#### 独立验证目录与本次临时产物

创建独立副本、输出、临时目录或私有缓存副本时，登记路径、创建者、调用/阶段、原有状态及保留需要，优先用本次独占新目录；不按名称、后缀或时间接管旧目录，共享缓存/原有文件保持原状。

谁创建谁收尾：Agent 仅处理其获准目录；宿主目录由宿主回收，Agent 引用实际收据。归属或范围外能力不明时披露，源码 `match` 不代表全调用清理完成。顺序为停止写入 → 保存并读回必要证据 → 回收可丢弃项 → 复查残留、原有文件与证据。已发布清单/结果、日志、报告、轨迹、身份收据、恢复依据及不可重建的必要输入不作垃圾，摘要不作备份；缺必要证据则保留目录并报告未完成。不跟链接越界、不跨挂载递归、不删被替换目录。

通过、失败、超时、中断或部分初始化均尝试有界收尾；无法确认进程停或安全删除则保留现场。宿主强杀不承诺即时回收，留登记/证据供后查，不自动重跑模型或修复。文件回收与进程退出分别记录；后续清理新增记录，不覆盖历史结果。

脚本只比较最终状态，不追踪全部写入或证明产物语义/归属。构建改写源码或生成代码需交付时核对验证对象，恢复一致不消除输入漂移；仅清非交付输出无需再编译，改必要输入则重评受影响验证。

### 校验与处理

使用原清单、采集返回的原摘要及完整根目录集合运行 `check`，核对本次[返回结果与绑定](#返回结果与绑定)：

`scripts/workspace_check.py` 的有序参数：

```json
["check", "--root", "/ci/work/sourcecode/repo-a",
 "--manifest", "/ci/healing-output/check-001-before.json",
 "--manifest-sha256", "capture返回的64位摘要",
 "--invocation-id", "invocation-001", "--candidate-id", "candidate-001",
 "--output", "/ci/healing-output/check-001-result-01.json"]
```

根据下表继续；每次调整后重新检查，不能把旧收据当成当前事实。“正常编译输出”“被 Git 忽略”“来源已明确”都不使 `mismatch` 成为通过；空目录也属于路径差异，`git status` 或只列普通文件的检查不能替代脚本。候选已被否决或决定放弃时，先按[候选撤销与基准](workspace-recovery.md#候选撤销与基准)处理，不按原候选盲目恢复文件。

| 脚本事实 | Agent 的处理 |
| --- | --- |
| `match` | 声明范围内已与编译前状态一致；再核对清理是否改变必要输入、修复依据与验证收据是否有效，不直接等同于修复成功 |
| `mismatch`：残留副产物 | 查明来源后安全清理，再校验；不能因其属于预期输出而保留并宣称通过，无法安全清理时报告缺口 |
| `mismatch`：差异看起来正是拟保留的候选 | 先核对是否在候选应用前误采了基准、或组内修改了候选；属实时按[基准缺失或时序错误的恢复](workspace-recovery.md#基准缺失或时序错误的恢复)处理。不能以“都是预期源码修改”豁免，也不为匹配错误基准撤销仍有效的候选 |
| `mismatch`：原有或仍有效的候选文件缺失/被改写 | 根据可靠的原始内容恢复误删误改，再校验；无法确认归属或恢复依据时暂停相关写入 |
| `mismatch`：差异确实应成为新的修复 | 重新评估并记录候选准入，保留旧校验事实；取得新的候选基准并重做受影响验证，不仅为了消除差异而重新采集 |
| `incomplete`、无结果或结果绑定不符 | 解决读取、范围、预算或漂移问题后重查；仍无法完成时按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)协作或结束，不能宣称已清理或校验通过 |

需要恢复基准或撤销候选时，**在相关恢复、重新采集或撤销前**读取[清理基准恢复与候选撤销](workspace-recovery.md)。正常清理不加载该分支；历史违规与原始比较事实仍保留。

## 结束与协作

- **成功交付候选**：适用本指南时，须有绑定当前候选与完整根集合的有效采集收据和最新 `match`，同时核对本次登记的独立目录及临时产物已回收或有明确的必要保留依据，确认清理未使必要验证失效，再按[结果判定](repair-and-verification.md#结果判定)判断成功。发布或交给 Patch 脚本前核对状态仍一致，发生相关变化时重查；之后保持待交付内容不变。
- **缺口报告或协作**：`mismatch`、`incomplete`、脚本不可用或恢复不安全不阻止输出报告、提问或移交。暂停不安全的写入，按[交互与移交](execution-modes.md#交互与移交)说明当前文件状态、残留、恢复依据和继续条件；不能声称清理完成或候选可安全提取。报告写入仍遵循[输出约定](output-delivery.md#输出方式)。
- **结束结果**：因清理/校验缺口无法完成修复时返回 `inconclusive`；另有已确认的禁修等终止原因时按通用结果判定，同时披露清理缺口。保留编译通过等实际观察，不将其升级为完整成功。

清理循环共用[调用预算](core-contracts.md#调用身份与限额)。恢复和校验本身不新增修复 Attempt；形成新完整候选并进入验证时按原规则计数。没有进展、预算耗尽或无法安全清理时结束或协作，不反复盲删。

文件一致性、修复是否成功和报告是否交付分别判断。把校验范围、基准引用、实际清理、最新结果与残留问题汇入[结果报告](result-report.md)，不另设人工审批流程或 Patch 提取协议。

## 脚本结果与异常

### 返回结果与绑定

运行期结果输出到 stdout JSON，参数错误可能只有 stderr；同时核对退出码和下列观察，不只看文件是否存在：

| 操作与退出码 | 含义 |
| --- | --- |
| `capture`：0 | 清单已完整采集、写入并读回；不是编译或清理成功 |
| `check`：0 | `match`，检查范围与原基准一致 |
| `check`：1 | `mismatch`，存在差异，文件未被脚本更改 |
| 两者：2 | `incomplete` 或参数错误；参数错误可能只有 stderr，不得当作通过 |

JSON 绑定实际根、调用/候选、观察时间、固定排除与缺口；`compared`/`not_compared` 标明覆盖维度。`added`/`missing`/`changed` 给出前后类型、哈希、属性，不建议删除。`counts` 是完整计数，`differences_truncated` 只表示详情限额截断，仍为 `mismatch`；可增加展示限额重查，不把未展示项当不存在。

`gaps` 保留错误码/原因，补充 `phase`、可确定的 `path` 和适用 `errno`，未知字段可空。`scan` 指源码观察，`manifest_read`/`manifest_validate` 指基准，`manifest_write`/`report_write` 指状态文件交付。读取失败不是文件缺失或 `mismatch`；按阶段处理，不为报告写入错误改源码。

### 状态文件与异常

- `--output` 可省略；提供时只能创建范围外的新文件。比较完成得到 `match` 或 `mismatch` 后才发布校验 JSON 报告；扫描、基准或范围检查失败时，stdout 返回 `incomplete`，不保证生成报告文件。重复校验使用新结果文件名或只用 stdout，不能覆盖旧证据，原清单不变。
- `capture` 写入并读回清单后才返回 `captured` 与摘要；没有成功采集收据的清单不能作为已确认基准。根据实际失败阶段处理问题，已有文件和检查观察分别保留。

状态文件发布或收尾出现异常时，先读取[状态文件异常](workspace-recovery.md#状态文件异常)，分别核对发布结果、stdout/stderr 与最终绑定；文件存在本身不证明成功。

## 支持范围与局限

- 比较普通文件内容、文件/目录权限、路径集合及链接目标，不跟链接读内容；不比较所有者、ACL、扩展属性、时间戳或硬链接拓扑。范围外目标/其他副作用另核对，不扩展 `match`。
- 只排除各根直属 `.git`，不排除 `.gitignore`/产物目录，无任意忽略参数。嵌套仓库、跨设备挂载、特殊文件返回 `incomplete`，须确认范围/补能力，不静默跳过；Git HEAD/index 按原合同核对。
- 采集/校验两次流式读取，核对期间身份/时间属性，漂移即不完整；不是原子快照，也不阻止写入。检查前停写并排除并发者，检查后仍可能漂移。
