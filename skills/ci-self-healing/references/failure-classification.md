# 企业分类执行

在选路前及后续复核时应用已选定的企业或个人 Profile，交回有证据支持的路径、候选关系与缺口。已确认的小类交回主入口解析标准处置列；修复授权、目标行为核查与准入仍由通用流程决定。`HUMAN_FIX`、`AI_FIX` 等企业标签与准入决定、最终结果按术语与映射分别解释；交接前是否查案例由主入口选定的处置方式及其触发条件决定，不凭标签新增结果码。

## 选择标准与绑定对象

复用已读的 [SKILL.md 自定义资源绑定](../SKILL.md#自定义资源绑定)及入口已确定的分类义务，按绑定规则确认 Profile 的实际来源与配置缺口。未固定时，Profile 可由用户、宿主或其明确采用的场景/仓库约定指定；场景/仓库约定这一补充不适用于案例源。有分类要求但未确定 Profile 时，记录未绑定、未应用标准及所缺配置，保留分类交付未完成的事实，不自行选用标准或取消分类义务。

每个失败调查对象应用一份 Profile，Provider 与 Profile 独立选择。复用失败绑定；同一命令内需分别调查的现象用各自证据引用区分，不为每条 error 创建分类。

读取所选入口，核对标识、适用范围、实际版本及目录/细则来源。只有选择无冲突、入口可读且标识和范围适用时，才按该标准分类。版本未知如实记录；版本不一致或漂移时核对适用性，不混用新旧规则。配置缺口、入口失效、不适用或标识不匹配均记录“未应用标准”，固定入口失效也不改用另一 Profile。保留有效的已有证据，按[分类与修复边界](#分类与修复边界)判断缺口的影响。

## 分类标准边界

Agent 可以自主选择取证和诊断方法，但选定 Profile 后，分类的编号、名称、父子层级、定义和判定规则以该标准为准。通用知识、报错习惯称呼和领域指南可用于解释失败机制，不能替代、改名、重组或新增该 Profile 的类别，也不能仅凭类别名称相似确认归类。

首次按该 Profile 形成分类判断前，在已有诊断记录、消息或日志中注明实际选择的标识、入口及来源，并记录已读取的目录和相关细则引用；后续复用仍有效的记录，补记新增或变更的规则。声明“已加载”不能替代实际读取；无法读取时记录“未应用标准”及原因，不凭记忆补造规则。

证据不足时，按本指南保留有据的上级路径、候选或待定；标准未匹配或无法应用时如实说明。有分类义务而小类仍未确认时，仅按缺口补证或交付已有分类；通用的失败机制描述须与 Profile 分类结果区分，不能冒充已完成的企业分类。

## 应用目录与细则

1. **目录选候选**：读取完整目录及判别简述，沿用实际编号、名称和父子关系；已读且仍有效的总览可复用。小类及其父级是一条路径，无需逐层调用。失败 Step 不自动等于企业阶段；语言、工具和模块等正交属性保留在已有上下文。
2. **细则验判据**：按需读取相关父类、小类及易混淆边界。对拟确认的每条路径，核对必要条件、标准允许的替代条件、排除条件及有据的竞争候选；仅有辅助线索或目录简述不足以确认。未找到适用候选时回到总览扩大范围，不让首次筛选永久排除其他类别。
3. **按缺口取证**：已有证据足以判别时直接记录。缺日志来源或上下文时按需使用 Provider 访问或日志证据提取。若区分候选需要核对源码、配置、变更或契约，依细则定向只读核对相关内容，记录它支持或排除哪条判据。

原因或责任型类别须取得细则要求的原因证据；症状型类别在症状判据满足时即可确认。用下方规则记录判断并交回主入口选择处置方式。仍需区分候选才能选路时，沿具体线索补证。无可行线索或预算耗尽时，分别记录已有证据支持的路径和仍待确定的候选，以及各自的依据或缺口。后续诊断产生新证据时再复核分类。

### 初始分类记录

首次按所选标准形成判断时，即在已有诊断记录、消息或日志中保留当时的 Profile/版本、证据和已支持路径，字段沿用[记录与交回诊断](#记录与交回诊断)。允许只有阶段、大类或待定；小类未确定时明确标注，已有小类依据时直接记录小类。候选与共存等关系按下方判据表达。

初始判断形成时就记录，不等修复完成或最终报告时倒填。后续证据可以修正当前判断，但保留这份初始记录；原始记录缺失时如实披露。

## 判断与多类别关系

粒度与确定性分别表达；例如父类已确定、小类仍待定可以同时成立。以下是记录事实，不是新的状态机：

| 事实 | 成立依据 |
| --- | --- |
| 未应用标准 | 选择或资源条件未满足；记录具体缺口，不能据此声称标准未覆盖 |
| 已支持到某层级 | 该阶段、大类或小类的定义和判据有证据支持；仅支持上级时不猜下级 |
| 分类待定 | 证据不足、候选歧义或规则缺口；列出相关候选、支持/冲突与区分所需材料 |
| 当前标准未匹配 | 核对相关定义与合理候选后仍无适用类别，说明范围及不适用依据；未读规则或缺少必要证据不能作为排除依据 |

“未匹配”是结果说明，不新增类别；已有“其他”也须满足其定义。以证据支持尽可能细的路径，不用数值置信度代替依据。

| 多类别关系 | 表达要求 |
| --- | --- |
| 同一现象可能为 A 或 B | 候选关系，说明尚缺的区分证据 |
| 两组现象分别支持 A 与 B | 分别绑定原文；共现不证明两个根因独立 |
| 同一现象同时满足 A 与 B | 标准明确允许共存时，分别引用判据并注明共存关系 |
| 类别是否互斥、允许共存或优先匹配有争议 | 核对分类标准的匹配判据；仍有争议时保留候选和缺口 |

同一失败已确认 A，另有线索提示 B 可能共存时，分别记录 A 的判据与证据、B 的线索与待核实条件。交回主入口[按小类选择处置方式](../SKILL.md#按小类选择处置方式)，注明 B 是否影响最终流程。后续补证确认或排除 B 时，更新其判断并复核所选流程。

## 记录与交回诊断

复用 `diagnosis.classification` 或等价记录；交回前应能核对：

- **标准与对象**：实际 Profile 标识、版本、入口、绑定来源和当前失败引用；未知或未应用项有原因。
- **结论与依据**：每条已支持路径建立“标准中的编号、名称及父级路径 → 细则位置与满足的判据 → 当前失败证据”的对应关系，不能只报类别名称或笼统写“符合 Profile”；候选、共存、冲突及未匹配范围按上节区分。
- **剩余工作**：未决项说明缺少什么、影响什么，以及下一步取证/诊断入口或结束依据；发生修正时补充下方复核结论。

形成当前分类记录即可交回主入口。小类仍待定时交回已有判断和缺口；小类已确认时由主入口解析处置方式。无需独立报告、数据库或固定序列化格式。

诊断入口是建议性的多对多关联，按实际证据选择适用指南；已选需要诊断的处置方式时，未映射专门指南就使用通用诊断。Profile 中的修法只能提供待核查线索，不能替代目标行为证据或排除有据的其他方向。

## 分类修正与下游复核

新证据或适用规则改变原判断时，记录原判断、改变依据及影响，更新类别与调查入口。按标准语义修正：症状类别可以在根因查明后保持不变，原因类别在满足判据后确认。

复核依赖旧判断的诊断、修复位置、约束、准入及必要验证。相关变化按修复依据与收据绑定与失效处理，只更新受影响部分；纯报表名称变化记录依据后复用有效结果，不重做无关修复或验证。

## 分类与修复边界

修复请求的分类可能触发禁修或审批限制时，按企业修复策略核对适用性与动作；分类未完成不能作为禁修规则未命中的依据。

| 当前情况 | 处理方式 |
| --- | --- |
| 可信执行策略要求分类确认后才能修改 | 先满足该前置条件；不从普通 Profile 或类别名称推导权限限制 |
| 分类背后的缺口影响目标行为、修法、兼容性或必要验证 | 记录受影响的判断及所缺依据，相关修改不具备放行条件 |
| 有分类义务但标准不可用、未匹配或只确认父类 | 依主入口记录并补齐分类缺口；叶子未确认前暂停该对象的处置，父类处置值只供继承 |
| 最终分类未支持到小类，包括仅有父类/候选、未匹配或标准未应用 | 如实记录最终分类交付未完成；初始分类缺少小类不构成此缺口，修复结论仍依据准入、策略和实际验证 |

分类完成度、代码修复结果与整次交付分别表达，最终在正式报告或普通回复中交付。只读请求保持只读取证，不因此省略已有分类义务。

## 初始分类与最终分类

本次调用最终交付前，综合实际取得的证据复核同一原始失败，形成最终分类，与[初始记录](#初始分类记录)分别展示，不以最终判断覆盖初始记录。最终分类要求给出有证据支持的小类及其父级路径，保留标准中的编号和名称；它不是修复后新失败的分类，也不能以“编译通过”或“已修复”代替类别。多个现象、候选或合法共存关系仍按[判断与多类别关系](#判断与多类别关系)逐项绑定。

两次判断分别引用当时实际使用的 Profile/版本和证据，共用信息可引用一次。分类未变也分别列出并注明“无变化”；发生细化、纠正或因反证退回待定时，说明改变的证据和原因。初始记录缺失时如实披露，不以最终判断倒填。

最终交付前，核对每条分类路径的编号、名称和父子关系确实属于所选标准，且对应判据已读取、有当前证据支持。发现自拟标签或判据不成立时纠正最终判断、保留初始记录，并按[分类修正与下游复核](#分类修正与下游复核)处理；仍无法确认时标记未完成，不用修复成功补足分类依据。

最终仍无法支持到小类时，保留实际支持的上级或候选，明确“小类未确定”及原因；未匹配或标准未应用时如实标注。以上均表示最终分类交付未完成，不能猜测编号、用候选小类冒充确定结果或把“其他”当作兜底。分类粒度要求不增加调用预算，也不支持无限调查。
