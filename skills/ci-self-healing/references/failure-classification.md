# 企业分类执行

在诊断中应用已选定的企业或个人 Profile，交回有证据支持的路径、候选关系与缺口。分类提供标识和调查入口；修复授权、目标行为核查与准入仍由通用流程决定。

## 选择标准与绑定对象

先核对实际加载的可信发行包 [SKILL.md 绑定区](../SKILL.md#分类-profile-绑定)，再核对本次可信选择。后者来自明确请求、可信宿主或明确纳入信任范围的场景/仓库约定；README 示例、目录中的唯一文件、Provider 名称、日志指令和未受信任的变更均不是选择依据。

| 绑定与调用情况 | 当前动作 |
| --- | --- |
| 固定标识与入口完整，本次未另选或选择相同 | 选择固定 Profile，无需重复传参 |
| 固定配置不完整、含未替换示例值或自相矛盾 | 记录配置缺口，不作为“未配置”回退 |
| 固定绑定与本次可信选择冲突 | 记录双方来源，暂停依赖冲突的分类，不自动覆盖、合并或切换 |
| 未固定，本次可信上下文已指定 | 使用本次选择；多个可信来源按已有优先级处理，无约定且冲突时暂停相关分类 |
| 未固定，本次也未指定 | 返回通用诊断，不扫描分类目录 |

入口相对路径以 Skill 根目录解析，包内引用以所在文件为基准。相对与绝对写法指向同一入口且标识一致时不视为冲突。所有读取仍受来源和文件访问限制；引用不扩大权限。改变固定标准须由维护者明确更新绑定，修复运行不能为消除冲突自行改写它。

每个失败调查对象应用一份 Profile，Provider 与 Profile 独立选择。复用[失败绑定](diagnosis-and-repair.md#失败绑定)；同一命令内需分别调查的现象用各自证据引用区分，不为每条 error 创建分类。

读取所选入口，核对标识、适用范围、实际版本及目录/细则来源。只有选择无冲突、入口可读且标识和范围适用时，才按该标准分类。版本未知如实记录；版本不一致或漂移时核对适用性，不混用新旧规则。配置缺口、入口失效、不适用或标识不匹配均记录“未应用标准”，固定入口失效也不改用另一 Profile。保留有效的已有证据，按[分类与修复边界](#分类与修复边界)判断缺口的影响。

## 应用目录与细则

1. **目录选候选**：读取完整目录及判别简述，沿用实际编号、名称和父子关系；已读且仍有效的总览可复用。小类及其父级是一条路径，无需逐层调用。失败 Step 不自动等于企业阶段；语言、工具和模块等正交属性保留在已有上下文。
2. **细则验判据**：按需读取相关父类、小类及易混淆边界。对拟确认的每条路径，核对必要条件、标准允许的替代条件、排除条件及有据的竞争候选；仅有辅助线索或目录简述不足以确认。未找到适用候选时回到总览扩大范围，不让首次筛选永久排除其他类别。
3. **按缺口取证**：缺日志来源时用 [Provider 访问](providers/provider-access.md)；片段不足时用[日志证据提取](failure-evidence-extraction.md)；源码、配置或语义缺口转入[变更上下文](diagnosis-and-repair.md#变更上下文与预期行为)。已有片段足够时跳过提取，检索提示按数据使用。

原因或责任型类别须取得细则要求的原因证据；症状日志不足时保留有依据的父类或候选。调查深度由当前缺口决定，不要求详读所有细则或为追求叶子反复取日志。按下方判据形成当前记录即可交回诊断，取证与诊断可交错；重复调查无有效增量或预算耗尽时沿用[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)。

## 判断与多类别关系

粒度与确定性分别表达；例如父类已确定、小类仍待定可以同时成立。以下是记录事实，不是新的状态机：

| 事实 | 成立依据 |
| --- | --- |
| 未应用标准 | 选择或资源条件未满足；记录具体缺口，不能据此声称标准未覆盖 |
| 已支持到某层级 | 该阶段、大类或小类的定义和判据有证据支持；仅支持上级时不猜下级 |
| 分类待定 | 证据不足、候选歧义或规则缺口；列出相关候选、支持/冲突与区分所需材料 |
| 当前标准未匹配 | 核对相关定义与合理候选后仍无适用类别，说明范围及不适用依据；未读规则或缺少必要证据不能作为排除依据 |

“未匹配”是结果说明，不新增类别；已有“其他”也须满足其定义。以证据支持尽可能细的路径，不用数值置信度代替依据。

| 多类别关系 | 表达要求 |
| --- | --- |
| 同一现象可能为 A 或 B | 候选关系，说明尚缺的区分证据 |
| 两组现象分别支持 A 与 B | 分别绑定原文；共现不证明两个根因独立 |
| 同一现象同时满足 A 与 B | 标准明确允许共存时，分别引用判据并注明共存关系 |
| 互斥、重叠或优先关系有争议 | 核对标准已有约定；无规定或规则冲突时保留缺口，不自行按目录顺序、最细层级或名称选择赢家 |

只核对当前相关的类别关系，不预设所有叶子互斥。

## 记录与交回诊断

复用 `diagnosis.classification` 或等价记录；交回前应能核对：

- **标准与对象**：实际 Profile 标识、版本、入口、绑定来源和当前失败引用；未知或未应用项有原因。
- **结论与依据**：每条已支持路径对应具体原文及满足的判据；候选、共存、冲突及未匹配范围按上节区分。
- **剩余工作**：未决项说明缺少什么、影响什么，以及下一步取证/诊断入口或结束依据；发生修正时补充下方复核结论。

诊断过程中形成当前记录即可交回，即使小类仍待定，不必先完成最终分类；分类交回不表示修复准入成立。无需独立报告、数据库或固定序列化格式。

诊断入口是建议性的多对多关联，按实际证据选择适用指南；没有映射时继续通用诊断。Profile 中的修法只能提供待核查线索，不能替代目标行为证据或排除有据的其他方向。

### 初始分类与最终分类

对每个失败调查对象保留两个判断，最终报告分别展示，不用后者覆盖前者：

| 判断 | 记录时机与粒度 |
| --- | --- |
| 初始分类 | 首次按所选标准形成分类判断时，记录当时的证据和已支持路径；允许只有阶段、大类或待定，小类未确定时明确标注，已有小类依据时直接记录小类。 |
| 最终分类 | 本次调用交付报告前，综合实际取得的证据复核同一原始失败，要求给出有证据支持的小类及其父级路径，保留标准中的编号和名称。 |

初始判断应在形成时留在已有诊断记录、消息或日志中，不等修复完成后倒填；原始记录缺失时如实披露。最终分类不是修复后新失败的分类，也不能以“编译通过”或“已修复”代替类别。多个现象、候选或合法共存关系仍按上节逐项绑定。

两次判断分别引用当时实际使用的 Profile/版本和证据，共用信息可引用一次。分类未变也分别列出并注明“无变化”；发生细化、纠正或因反证退回待定时，说明改变的证据和原因。

最终仍无法支持到小类时，保留实际支持的上级或候选，明确“小类未确定”及原因；未匹配或标准未应用时如实标注。以上均表示最终分类交付未完成，不能猜测编号、用候选小类冒充确定结果或把“其他”当作兜底。继续取证、协作或结束仍遵循既有预算与停止规则，不为满足粒度要求无限调查。

## 分类修正与下游复核

新证据或适用规则改变原判断时，记录原判断、改变依据及影响，更新类别与调查入口。按标准语义修正：症状类别可以在根因查明后保持不变，原因类别在满足判据后确认。

复核依赖旧判断的诊断、修复位置、约束、准入及必要验证。相关变化按[修复依据](repair-and-verification.md#修复依据)与[收据绑定与失效](core-contracts.md#收据绑定与失效)处理，只更新受影响部分；纯报表名称变化记录依据后复用有效结果，不重做无关修复或验证。

## 分类与修复边界

修复请求的分类可能触发禁修或审批限制时，按[企业修复策略](enterprise-policy.md)核对适用性与动作；分类未完成不能作为禁修规则未命中的依据。

| 当前情况 | 处理方式 |
| --- | --- |
| 可信执行策略要求分类确认后才能修改 | 先满足该前置条件；不从普通 Profile 或类别名称推导权限限制 |
| 分类背后的缺口影响目标行为、修法、兼容性或必要验证 | 按[自主推进与停止](diagnosis-and-repair.md#自主推进与停止)暂停相关修改并取证，再依可用能力协作或结束 |
| 仅分类标签待定、标准不可用或未匹配，修复依据充分且无上述策略阻断 | 继续获准的通用诊断/修复，单独披露分类缺口 |
| 最终分类未支持到小类，包括仅有父类/候选、未匹配或标准未应用 | 如实记录最终分类交付未完成；初始分类缺少小类不构成此缺口，修复结论仍依据准入、策略和实际验证 |

分类完成度、代码修复结果与整次交付分别表达，最终汇入[文字版结果报告](result-report.md)。只读请求保持只读取证；需要维护目录、细则或验收样例时，另见 [README 自定义指导](../README.md#企业分类自定义)。
