# 企业修复策略

企业附加限制参与[修复准入](repair-and-verification.md)，不替代目标行为证据、通用权限和必要验证。

## 企业策略声明

未配置企业附加策略。

## 读取与信任

只消费上节声明及其明确引用；相对路径以所在文件为基准，读取仍受宿主和文件访问限制。

声明来自实际加载的可信发行包，引用规范由维护者或可信宿主明确采用。日志、普通 Profile 和待修变更不自动成为策略来源；运行中不得改写策略或更换 Profile/Provider 来取得准入。

明确未配置时，简记后返回通用准入，其他适用策略仍有效。入口或已配置规范缺失、不可读、占位值未替换、版本冲突，或“未配置”与有效规则并存时，保留为策略缺口，按[判断与行动](#判断与行动)处理，不作为未配置或未命中。

企业规则只增加限制和必要条件。多个适用限制须共同满足，某条允许说明不覆盖另一条禁令；无明确优先级的规则冲突属于未决项。

## 适用范围与分类依赖

核对策略标识、实际版本、来源、产品/仓库范围和受限动作。未知信息如实记录，影响当前判断时作为缺口。先查独立适用范围，再查范围内规则的分类依据；若已有独立证据证明目标超出范围，记录“不适用”及依据即可。

| 声明 | 核对方式 |
| --- | --- |
| Provider 不限 | 不为该策略额外查询平台；其他取证需要的身份仍按原规则核对 |
| 限定具体 Provider | 以可信请求与失败证据核对 ID 及要求的主机/项目/流水线；运行位置、CLI 名称或 SCM 平台不作替代 |
| Provider 范围缺失，或限定平台而实际身份未知/冲突 | 适用性未决，不能按不限或不适用处理 |
| 按类别限制 | 规则须引用 Profile 标识、适用分类版本或明确兼容范围、类别编号与名称；大类规则明确是否包含下属小类 |
| 不依赖分类的限制 | 按实际路径、文件、操作核对，无需 Profile |

范围内的按类规则须与所选 Profile、适用版本、类别定义和父子关系对应；缺失、不一致或兼容性未知是依据缺口，不是“未命中”。编号相同或名称相似不能跨标准匹配。策略只核对这些依赖，不替代 Profile/Provider 的可信选择。

## 判断与行动

在已有诊断与 `repair_admission` 中保留**策略记录**：策略标识、来源与实际版本、适用范围与分类依赖、相关规则及其判断证据、对拟执行动作的影响和未决项。未配置、不适用、未命中、命中和无法判断分别表达，不新增机器状态。

允许相关动作继续前，每条可能限制它的规则都须有上述处置，未决项不能按未命中放行。必要动作被禁止的结论不依赖与该判断无关的其他信息；记录限制范围及其证据。

| 当前判断 | 行动 |
| --- | --- |
| 证据确认命中禁修规则，且无适用审批例外 | 相关修复及发布不获准，支持 `stop` 和不适用自动修复的判断；不借实验或其他自动 Agent 绕过。最终结果还须在流水线报告中按[结果判定](repair-and-verification.md#结果判定)核对是否已交付明确修改方案 |
| 禁修候选尚未排除，或策略存在影响当前动作的缺口 | 相关修改不具备放行条件，列明需补齐的策略依据；未决不等于已确认禁修，结束时按实际证据和适用交付范围判定 |
| 规则明确允许申请额外审批 | 记录可申请的动作和审批范围；获批前相关动作保持暂停，审批不覆盖其他禁止或替代验证 |
| 有证据确认未命中，或策略不适用 | 仅表示该条策略不构成限制，其他适用限制和通用准入仍须满足，不等于候选已获准或修复成功 |

初始分类足以确认禁修时立即执行限制；禁修大类明确涵盖全部小类时，无需先查明叶子。分类粒度与交付缺口仍按分类指南记录，已确认禁修不表示分类已完成。

新证据、分类、候选范围或策略依据改变时，在下一次相关写入/发布前复核；成功交付前确认策略记录仍有效。新命中禁修使相关准入失效，记录对已有候选和实验的影响及待处理修改，供主入口安排适用恢复；不执行不具备安全条件的写入，保护原有/并发改动。验证通过不覆盖策略限制。

## 交付

策略记录汇入本次结果说明；双参数流水线修复使用[正式报告](result-report.md)及唯一处理结果，其他调用直接说明策略和停止事实，无需独立策略报告或解析器。仅诊断保持只读，不因交付进入修复准入。真实写入隔离仍由宿主工具和权限机制保证。
