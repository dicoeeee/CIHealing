# 知识库工作流

> [!note]
> 这是当前工作流的初稿。使用一到两周后，根据真实的记录习惯更新它，而不是迁就它。

相关规则：[[AI 使用边界]] · [[来源约束知识规则]]<br>
专题扩展：[[CI 自愈专题工作流]]

## 核心原则

- 先收集，后整理。记录当下不需要决定最终位置。
- 文件夹表示主要归属；双链表示概念、来源和使用关系。
- 每条笔记只做一件事：保存来源、表达观点、推进项目或提供导航。
- 只维护真正会再次使用的内容。

## 目录总览

| 目录 | 用途 |
| --- | --- |
| `00_Inbox/` | 新剪藏、临时记录和待判断资料的唯一入口 |
| `10_Projects/` | 有明确结果和完成条件的短期工作 |
| `20_Areas/` | 长期维护的责任领域；`Journal/` 存放每日笔记 |
| `30_Resources/` | 可长期复用的学习资料和主题知识 |
| `40_Archive/` | 已结束、不再活跃但需要保留的内容 |
| `50_MOCs/` | 主题导航页和知识地图 |
| `80_Admin/` | 知识库的规则、工作流、回顾和 AI 变更记录 |
| `90_Templates/` | 用于新建笔记的模板，不存放正式知识内容 |
| `90_Private/` | 私密内容隔离区；不进入 Codex 或其他 AI 的默认处理范围 |
| `99_Attachments/` | 图片、PDF 和其他附件 |

其中 `30_Resources/**/Sources/` 与 `30_Resources/**/Knowledge/` 执行 [[来源约束知识规则]]：只保存公开原文能够直接支持的内容；推理、判断与方案必须迁入非严格目录。

## 1. 收集

所有新信息先进入 `00_Inbox/`：

- Web Clipper 剪藏的网页和文章
- 临时想法、会议记录和待读资料
- 需要稍后判断价值的文件或链接

收集时只保留标题与来源链接。不急于分类、提炼或建立很多标签。

## 2. 处理 Inbox

每天或每两天处理一次 `00_Inbox/`。对每条内容做一个决定：

| 判断 | 去向 |
| --- | --- |
| 有明确结果与结束条件的工作 | `10_Projects/` |
| 长期需要维护的责任领域 | `20_Areas/` |
| 可长期参考的学习资料或主题知识 | `30_Resources/` |
| 暂时没有价值但希望保留 | `40_Archive/` |
| 由 AI 生成且尚待确认的内容 | `00_Inbox/_AI_Review/` |

处理网页、书籍或课程内容时，普通资料可使用 [[资料笔记]]。进入 `Sources/` 或 `Knowledge/` 的资料必须使用来源约束模板，原文事实与个人想法不得混写。

## 3. 建立连接

每条有价值的笔记完成后，补充一到三个有意义的链接：

- 资料笔记链接到它补充、反驳或说明的概念。
- 常青笔记链接到来源笔记和实际应用场景。
- 项目笔记链接到相关资料、决策和任务。

不要因为词语相同而强行链接。优先链接“这条内容解释了什么”“从哪里来”“在哪里会用到”。反向链接由 Obsidian 自动生成，不需要双向手工重复。

## 4. 沉淀知识

当一个观点可以脱离某篇文章、在未来反复使用时，用 [[常青笔记]] 将它写成独立的结论。

一条常青笔记应说明：

- 核心观点是什么
- 为什么成立或如何理解
- 一个具体例子
- 它与哪些已有笔记相关

普通资料笔记保存“别人说了什么”；普通常青笔记表达“我认为可以长期复用什么”。严格目录中的 Knowledge 是例外：它只重组公开原文能够共同确认的知识，不保存“我的推理”。

## 5. 推进项目与日常记录

- 每天使用 [[每日笔记]] 记录重点、过程、收件箱和明日行动。日记保存在 `20_Areas/Journal/`。
- 有明确目标、完成标准或期限的事项使用 [[项目笔记]]，存放在 `10_Projects/`。
- 项目笔记只保留目标、下一步、资料链接、决策和完成标准；原始资料仍放在相应的资料笔记中。

## 6. 建立主题导航

当一个主题已有约五到十条重要笔记时，使用 [[MOC 导航页]] 在 `50_MOCs/` 建立导航。

MOC 是人工维护的主题地图：按自己的理解链接核心笔记、资料来源和待探索问题。它不是把所有相关文件自动罗列出来的数据库。

## 7. 每周回顾

每周预留约二十分钟：

- 清空或处理 `00_Inbox/`
- 检查活跃项目的下一步行动
- 将过期资料移到 `40_Archive/`
- 从一两条资料笔记中提炼常青笔记
- 更新重要 MOC 的入口链接
- 执行 Git 备份

```bash
git add .
git commit -m "weekly review"
git push
```

## 8. Codex 与 AI 自动化

Codex 可以协助摘要、建议标签、寻找相关笔记、生成 MOC 草稿和周回顾。

- AI 未确认的输出先放入 `00_Inbox/_AI_Review/`。
- 自动生成内容需要 `ai_generated: true`，并尽可能保留来源链接或来源笔记。
- 不让 AI 默认读取 `90_Private/` 或任何 `ai_access: false` 的笔记。
- 不让 AI 静默删除笔记、批量移动笔记或重写成熟笔记。
