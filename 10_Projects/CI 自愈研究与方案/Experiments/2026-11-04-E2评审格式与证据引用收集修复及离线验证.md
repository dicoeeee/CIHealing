旧评审器把“表达形式不匹配”和“评审信息真正缺失”混在一起。例如，19 项齐全的字典也会报“缺项或重复”；合法证据的精确资源名会报未知引用；额外备注会导致整份输出被丢出可收集范围。新收集器区分这些情况，并保留每一步转换、原始意见、规范化意见、证据映射和来源摘要。

## 2. 可兼容的形式与不可补齐的内容

### 2.1 三类格式处理

1. **字符串内的未转义 Tab**：仅修正其 JSON 编码，解码后的 Tab 字符、原因文字和结论保持不变。不裁剪正文、不提取 JSON 子串，不修复围栏、截断、多对象、未知转义或其他未转义控制字符。
2. **19 项字典转换为数组**：仅在键集合恰好包含全部 19 项时转换。键用作原子项 ID；若行内已有 ID，必须与键相同。缺项、未知项、冲突和重复键均拒绝，绝不填入默认 pass 或 not_applicable。
3. **额外 `evidence_note`**：明确接受非空字符串备注，并在规范化意见中原样保留。不是删除备注后放行，也不由收集器重新解释备注中的语义。

所有 JSON 对象层级都拒绝重复键，拒绝 NaN/Infinity，检查 summary、reason、status、evidence 的类型和内容。每个原子项仍必须恰好出现一次；pass/fail/not_applicable 仍要求非空证据；总评仍必须与逐项状态一致。

### 2.2 精确引用注册

引用必须落在当前冻结 packet 的证据集合内。仅当以下绑定全部成立时，才把资源名转换为一个已有的工具结果事件 ID：

- 原生 `load_skill` 或 `read_skill_resource` 属于 `ci-self-healing`。
- call_id 唯一配对，调用先于返回，调用与返回的 session/invocation origin 一致。
- 返回明确标记 `matched_full_body=true`，资源键与冻结资源正文完全对应，正文 SHA-256 一致。
- 对应结果事件 ID 已在该 packet 注册，且事件 ID 不歧义。

不采用大小写折叠、前缀/近似名称匹配、跨试次借用 ID，也不删除错误引用以使评审通过。提示词同步给出已确认资源名到事件 ID 的索引，要求模型直接输出实际 ID。该提示词调整尚未通过新的模型执行验证；本轮验证的是收集代码对已有记录的行为。

### 2.3 历史记录来源核对

回放先核对原进程完成状态和进程收据、请求模型及 profile 摘要、CLI stdout 与 public-response 一致性、会话身份与会话文件摘要。再从原生轨迹重新验证模型交换收据，并检查冻结 packet、原提示词和给模型的 packet 绑定。来源核对失败时，不进入意见接收流程。

新运行路径会另写 `collection.json`，保留原始输出；只有收集成功才发布规范化 `verdict.json`。本轮未调用该模型运行入口。历史回放函数只读，所有新结果集中写入新的 E2 分析目录。
