# 图谱驱动的失败上下文裁剪

> [!warning] 候选边界
> 本文是基于 Nx 公开 Project Graph 与 Task Graph 数据模型提出的自有设计候选，不代表 Nx Self-Healing CI 已公开采用本文的查询、裁剪、补丁限制或验证算法。Nx 公开事实以 [[CI 自愈上下文机制 - Project Graph]] 为准。

## 要解决的问题

只依赖失败日志或全仓检索，难以同时表达失败任务、项目边界、依赖关系和可能受影响的下游范围。候选需要回答：是否应利用项目图和任务图构造与失败绑定、范围受控且保留来源的修复上下文。

## 公开机制依据

- [[CI 自愈上下文机制 - Project Graph]]记录 Nx 公开的 Project Graph、Task Graph、配置对象、依赖数据和图生成机制。
- 本文不把公开数据模型扩写成 Nx Self-Healing CI 的内部行为；下面内容均为本地候选设计。

## 候选机制

为每次 CI 运行生成与提交版本绑定的图快照。失败发生后，从失败任务映射到任务节点和所属项目，再按显式预算查询必要的依赖、被依赖项目、任务配置和相关文件，形成修复上下文包。

候选流程：

```text
失败事件
  → 任务标识
  → Task Graph 节点
  → 所属项目与目标配置
  → Project Graph 邻域查询
  → 带来源、完整性和截断信息的上下文包
```

图数据还可以作为补丁范围检查和验证计划的输入，但不能单独决定候选是否获得修改或写回权限。

## 职责与非职责

| 负责 | 不负责 |
| --- | --- |
| 表达项目、任务和依赖关系 | 直接判断代码根因 |
| 帮助缩小需要读取的仓库上下文 | 证明图中没有记录的关系不存在 |
| 记录图快照版本、完整性和查询截断 | 把图距离直接等同于允许修改范围 |
| 为影响范围和验证计划提供结构化输入 | 代替补丁硬校验、权限控制或 Required Checks |

候选的修改范围授权仍应由 [[CI 自愈策略控制平面架构]] 独立判断。

## 本地适用条件

- CI 运行能够稳定识别失败任务及其提交版本；
- 图快照与失败提交绑定，并记录生成器和配置版本；
- 图构建失败、部分完成或存在警告时能够显式降级；
- 动态依赖、隐式依赖和跨仓库关系的覆盖缺口能够被记录；
- 上下文查询具有深度、节点数、外部依赖和文件数量预算；
- 查询结果保留排序、截断和来源信息。

## 替代方案与冲突

- 全仓语义检索，不使用结构化依赖图；
- 只按目录、CODEOWNERS 或服务目录映射上下文；
- 只从失败日志和变更文件选择上下文；
- 使用独立的组织级服务目录或调用图，而不是构建工具图。

图裁剪可以与日志检索、变更文件和语义检索组合；如果把图当成完整世界模型，则会与实际覆盖缺口冲突。

## 待验证问题

- 图谱裁剪相对全仓检索减少了多少上下文，同时遗漏了多少根因相关文件；
- 查询方向、深度和排序对定位成功率的影响；
- 真实 CI 中图快照不完整、陈旧或无法映射失败任务的比例；
- 非构建工具任务和跨服务依赖如何补充；
- 基于图生成的验证计划是否遗漏应执行的回归任务；
- 候选补丁导致图变化时是否需要扩大验证或人工复核。

## 决策进展

- 当前状态：`captured`
- 尚未决定图的权威来源、生成时机、快照格式、查询预算或降级策略。
- 进入 `discussing`：明确目标故障类型和图覆盖范围。
- 进入 `shortlisted`：完成上下文召回率与成本实验设计，并列出需要 ADR 的边界。
- 进入 `adopted`：必须关联已接受 ADR。
