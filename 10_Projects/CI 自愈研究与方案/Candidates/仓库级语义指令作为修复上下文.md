# 仓库级语义指令作为修复上下文

> [!warning] 候选边界
> 本文是从 Nx `.nx/SELF_HEALING.md` 公开机制得到的自有设计候选，不代表 Nx 的未公开实现，也不表示本方案已经决定采用。Nx 公开事实以 [[CI 自愈上下文策略 - SELF_HEALING 指令]] 为准。

## 要解决的问题

CI 日志和代码本身不一定包含仓库团队对已知故障、修复偏好、禁止修改区域和架构边界的显式说明。候选需要回答：是否应为修复 Agent 提供一个随仓库版本管理、由团队维护的语义上下文入口。

## 公开机制依据

- [[CI 自愈上下文策略 - SELF_HEALING 指令]]记录 Nx 已公开的文件位置、格式、内容类型、优先关系和配置状态入口。
- 本文不重复扩展这些事实；下面内容均为面向本地方案的候选设计。

## 候选机制

在仓库中维护一份 CI 修复专用的自然语言指令文件，并允许它引用少量经过治理的架构或工程文档。修复流程读取该文件及其版本信息，形成带来源的语义上下文，用于影响故障解释、候选生成和人工复核提示。

候选内容可以覆盖：

- 已知故障模式及其识别线索；
- 团队偏好的修复方法；
- 不应修改或必须人工复核的区域说明；
- 已注册确定性修复器的使用提示；
- 需要补充读取的架构和工程文档。

## 职责与非职责

| 负责 | 不负责 |
| --- | --- |
| 为候选生成提供仓库语义上下文 | 授予文件、分支或写回权限 |
| 表达团队偏好和需要关注的边界 | 代替结构化策略和补丁硬校验 |
| 将上下文变更纳入仓库版本历史 | 证明 Agent 已逐条遵循全部指令 |
| 为人工复核提供可追溯输入 | 代替 CI 验证、Required Checks 或人工决策 |

确定性权限和补丁控制仍属于 [[CI 自愈策略控制平面架构]] 的职责，不能由自然语言指令扩大。

## 本地适用条件

- 指令文件有明确的维护者和评审流程；
- 每次运行能够记录所读取的文件版本或内容指纹；
- 引用文档的读取范围、递归深度和失效处理有明确约束；
- 自然语言指令与结构化控制冲突时，确定性控制不会被放宽；
- 缺失、解析失败和上下文截断能够被观察，而不是被当作指令不存在。

## 替代方案与冲突

- 不设专用文件，只依赖代码、日志和通用仓库文档；
- 只使用机器可解析的结构化配置，不提供自由格式语义上下文；
- 由平台在运行时注入说明，而不把说明保存在仓库；
- 将通用开发指令与 CI 修复指令合并在同一文件中。

它与结构化策略是互补关系；如果二者被设计成可以相互授权，就会产生职责冲突。

## 待验证问题

- 不同故障类型下，Agent 对仓库指令的遵从率和误解率；
- 专用文件相对通用仓库文档是否改善上下文命中；
- 引用文档数量、长度与修复质量和上下文成本的关系；
- 指令冲突、陈旧内容和缺失文件能否被稳定发现；
- 生成前提示与生成后确定性校验各自减少了多少越界候选。
