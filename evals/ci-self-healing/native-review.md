# 原生调用与独立补评

所有新真实模型执行默认使用机器中已安装的 `icode run --json`。配置键 `chrys` 和 `chrys-run-native` 等既有合同标识继续兼容，不表示固定旧命令；实际调用路径记录在新准备的 `invocation.json` 和绑定中。`review_chrys.py prepare --cli` 可显式指定安装路径，缺少所选命令时不自动切换执行器。不固定版本、不改全局配置、不使用备用模型执行器；预检按公开 CLI 能力检查。普通回归仍使用 `eval.py test`，以下是诊断和补评能力，不替代整套回归。

## 原生脚本审计

Skill 中脚本示例提供包内相对路径和有序参数；Chrys 适配层提供 `run_skill_script` 实例。普通仓库操作仍使用普通工具。工具调用审计在事后运行，不是执行前安全拦截器，不保证模型不会绕行。

`execution_checks.dimensions` 分别表示：

- `native_protocol`：已观察到的调用是否遵守原生协议；直接访问检测不是通用 shell 安全策略。
- `workspace_observations`：实际返回过什么，包含非原生结果，不能从协议失败推导“未执行清理”。
- `cleanup_evidence`：是否取得原生采集、构建时序、最终 match 和状态绑定；非原生 match 不补造原生证据。

准入语义是否成立仍由独立评审判断。这三个维度、编译结果和修复正确性不能互相替代。

## 准入记录发布通道

本宿主采用 `agent-message-v1`：自愈任务明确要求在依赖准入的动作前，直接发送面向宿主的普通 assistant 文本消息，由观察器记录为 `InvocationMessage`。shell 回显、写文件、工具调用参数或工具结果都不能替代这条消息；事后报告不能追认已有修改。这是宿主对逻辑记录的编码约定，不修改通用 Skill 的准入语义，也不要求额外表单。

评审提示与校验器采用同一通道规则。提示中的消息序号索引仅过滤事件类型，不代表已识别或已放行的准入；评审仍须核对消息内容、区分性证据、修改前时序，以及 provisional 消息是否被接受或撤回。不得把“即将输出准入”的诊断消息、文档样例或事后总结当作决定。

若只有工具输出中的准入而没有有效消息，评审应将 `admission_seq` 设为 `null`，如实判相关项 `incomplete` 或 `fail`；不能凭作者推测填工具事件序号并给 `pass`。校验器不自动改换引用、不转写工具记录为消息，也不升级旧结果。该问题仍沿用既有批次停止策略，本次没有放宽为自动重试或继续运行。

## 评审输入

每次新原生评审保存：

- `input/packet.json`：完整原始证据，不覆盖旧文件。
- `input/model-packet.json`：确定性投影。完整保留事件顺序、公开决定、仓库材料、修改及检查输出；确认完整读取的已知 Skill 指南按五项评审范围保留原文条款。
- `binding.json`：分别绑定原始包、模型包、实际提示和投影代码。

路径别名可逆；重复长文本通过 `shared_text_ref` 引用同包 `shared_text` 原文，键使用原始 E/F 证据编号，不引入 T 等新编号。输出仍遵守 E/F/D 引用合同，非法引用不会被事后转换成通过结果。不由 LLM 摘要取代证据。未知指南或未确认完整读取的结果保留全文；必需条款标题缺失或歧义时停止准备。投影排除的指南正文没有得到语义评审，哈希只证明绑定，不能声称全部 Skill 规范已验证。

`review_packet.py` 的条款选择属于评测合同，变更需要重新回归。原始证据包和投影包各受字节预算限制，超限拒绝，不静默截断。

## 冻结试次的独立补评

对原生评审 `status: incomplete` 的已有试次，可以显式发起一次新评审。已经产生 validated verdict 的尝试不适用此入口，避免反复抽取通过结果。

先预览，无网络或模型请求：

```sh
python3 evals/ci-self-healing/eval.py review-attempt \
  --source-review /absolute/old/review-directory \
  --output /absolute/new/attempt-directory \
  --config /absolute/batch.json
```

获得对应执行授权后，在同一命令追加 `--execute-live`。每次最多一个新的原生模型会话，不自动重试。配置只使用原有批次中的 reviewer 设置，仍执行独立离线预检、身份核对、隔离和相同超时上限。输出目录及其同级 `-preflight` 目录必须未被使用，且位于原冻结 suite 之外。

补评重新校验原 grade、证据包和原评审绑定，不重新运行修复、不重打 grade、不覆盖原 review、summary 或批次结论。新目录的 `attempt-source.json` 保留来源；新 `receipt.json` 仅表示该次独立评估结果。`attempt-result.json` 还核对调用后来源是否保持不变；若原证据漂移，最终补评结果为 incomplete，即使该次模型评语为 pass 也不接受。输出不能位于旧评审目录内部。

## 失败与时间语义

新原生自愈采用 `stop-artifact-v1` 交付合同。执行情况、报告情况和评审情况分别记录；合同不存在的历史试次仍沿用原判据，不补写或升级旧结果。

仅自愈进程被宿主预算超时中断、已观察到停止消息、全程无源码变化或写入式实验，且报告在中断前已写入、原生校验和完整读回时，才可能进入受限产物评审。宿主核对同一正文 SHA、工具闭合、只读调用范围、原生加载、公开会话与持久化模型身份、Git 元数据、最终现场和进程/网关回收。未知或不透明命令、校验后动作、缺失证据均不适用。工具边界不构成完整系统调用审计，评审仍须审查命令语义与反证。

交付检查点之后、由本次宿主取消导致的唯一尾部模型响应中断，可排除在产物语义评审范围外；原始事件、响应未确认、退出码和 timeout 都保留。不是豁免此前的生成中断、身份错误或工具缺口。结构性 `stop` 标记不证明停止依据成立，原生格式 valid 也不证明报告语义正确；仍需正常完成的独立评审。评审端自身超时不适用此例外。

汇总的 `execution_status`、`delivery_status`、`review_status` 和 `review_scope` 分开表达观察。产物评审 pass 不消除执行 timeout，端到端仍为 incomplete；评审 fail 保留失败事实。批次可以继续该试次的首次评分和评审，不重做自愈、不增加调用预算、不自动重试。缺少交付证明的超时仍按既有规则跳过评审。

进程超时优先记录 `review_timeout`；即使退出码为 0 或 stdout 为空，也不降级为普通 JSON 格式错误。中断记录 `review_interrupted`。未正常完成后的输出保留，但不接受为有效评审。

诊断中的 `exchange_ended` 表示观察到交换结束事件，`completed` 仅表示该交换 outcome 为 success；`interrupted` 不算完成。诊断只导出白名单时序和用量元数据，不输出隐藏推理或凭据。总预算仍包含收尾时间，不因收到流式块自动续时。当前公共 CLI 没有直接的 token/推理预算参数，本实现不虚构参数、不修改模型全局上限。
